# 用量与积分

入口：设置 → 用量与积分。页面复用当前登录用户、服务地址和已选择的组织；切换身份或组织后会清空之前的页面数据。

## 已接入的能力

| 页面     | 数据                                                | 现有接口                               |
| -------- | --------------------------------------------------- | -------------------------------------- |
| 概览     | 当前套餐、权益、周期额度、已扣/剩余积分、个人积分   | `GET /api/membership/me`               |
| 概览     | 当前与历史套餐周期                                  | `GET /api/membership/me/periods`       |
| 用量分析 | 7/30 天积分趋势，会话/Assistant/模型积分消耗前 5 名 | `GET /api/membership/me/overview`      |
| 扣费明细 | 按小时、会话和模型等维度聚合的记录，分页与模型筛选  | `GET /api/membership/me/usage-summary` |
| 扣费明细 | 所选分组的逐笔扣费积分及其来源                      | `GET /api/membership/me/usage`         |

没有增加数据库字段、埋点或服务端统计。自动充值、限额重置、代码审查、插件调用和技能使用统计不在本次范围内。现有消息统计接口面向管理场景或单个 Assistant，也没有作为个人全局统计展示。

## 统计口径

- 用户界面统一展示积分，不显示 Token 数量或提供 Token 指标切换；底层已有统计接口保持不变。
- 积分余额、周期记录、汇总、排行、每日数据及逐笔扣费统一四舍五入到整数并使用千位分隔；图表坐标和提示同样显示整数。计算与汇总仍使用接口原始精度，剩余百分比保留最多两位小数。
- 套餐积分属于当前组织。个人积分是账号在当前租户下的共享余额，分开显示。
- 分析和扣费查询均显式限制当前组织及当前用户。用户身份和组织请求头由 Electron host 构造，renderer 不能指定其他用户或组织。
- 日图表按服务端的 UTC 日期分桶，时间范围包含今天；会员周期和逐笔记录时间按本机时区显示。
- 积分消耗与积分扣除可能不同，尤其是存在未扣费的模型消耗时。分析展示服务端 overview 的口径，明细仅展示已有扣费台账，不从 `callCount` 推算消息数。
- 排行展示服务端排序后的前 5 项，因此没有伪造“更多”排行或完整模型列表。模型筛选支持完整名称，也可点击排行直接带入会话、Assistant 或模型条件查看扣费记录。
- 明细保留全部分组维度。API 无法表达的空维度由 host 在每页结果中精确匹配，继续分页使用原始记录游标，避免混入其他分组。
- 无限额度保留为不限额；权限拒绝、接口未提供、未登录及无记录分别展示，不将接口错误当作零用量。

## 开发和验证

```sh
corepack pnpm --filter @xpert-ai/desktop build
NODE_OPTIONS=--experimental-strip-types corepack pnpm --filter @xpert-ai/desktop test
node apps/desktop/scripts/preview-usage.mjs
```

当前 Node 22.17.1 运行仓库已有 TypeScript 导入测试需要 `--experimental-strip-types`。预览地址为 `http://127.0.0.1:4396/tests/fixtures/usage-preview.html`，使用独立测试数据和正式页面组件，不访问真实账户。页面顶部可选择正常、空记录、403、404、无限额度及未开通会员场景；测试入口不进入生产构建。

实际接口已完成只读联调：会员、周期、overview 和汇总记录均通过。当前授权组织无扣费记录，因此逐笔扣费和有数据分页由 fixture/host 测试覆盖；没有为验收制造真实扣费。

图表随用量页面延迟加载，避免进入应用启动包。已验证生产构建和浏览器 renderer；未制作新的安装包或执行打包后原生应用验收。

## 开发进程更新

Vite 只会热更新 renderer。变更 `electron/usage.cjs`、`service.cjs` 或 `dispatch.cjs` 后，需要退出并重新启动桌面开发进程。旧主进程会以 `Unsupported operation.`（403）拒绝新增方法；页面现在保留错误标识并明确提示重启，不再把这种情况解释为组织权限不足。共享 Tabs 使用 `line` 变体，避免默认卡片选中阴影叠加到下划线样式。

## 有用量但无扣费记录

`me/overview` 汇总模型使用事实及去重后的扣费数据；`me/usage-summary` 和 `me/usage` 仅查询 `usage`、`personal_usage` 扣费流水。因此分析有积分消耗，不代表当前用户和组织一定有扣费流水。明细页在无记录时解释这一差异，提供清除筛选和查看用量分析入口，不展示空明细选择器与无效分页。

通用模型使用台账接口受 `MODEL_USAGE_MONITOR` 管理权限保护，当前个人页面未接入该接口。没有改变服务端统计、结算或权限。
