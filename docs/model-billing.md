# 模型费用与汇率结算

模型调用按提供商返回的实际用量计价，账本保留原币金额、原币币种、结算金额、结算币种及本次采用的汇率。会员积分沿用人民币计价规则，当前结算币种只支持 `CNY`。

## 配置

平台统一配置位于 `IPluginConfig.billing`，不再使用模型专属的单一美元汇率字段：

```ts
billing: {
  settlementCurrency: 'CNY',
  exchangeRates: { USD: '7.2', EUR: '7.8' }
}
```

`exchangeRates` 的键为大写三位来源币种，值为正数十进制字符串，含义是「1 单位原币兑换多少结算币」。例如 USD 费用 0.29 按 7.2 结算为 CNY 2.088。配置中的数值仅为示例，不是实时汇率。

环境变量在 `packages/config` 启动边界读取：

```dotenv
BILLING_SETTLEMENT_CURRENCY=CNY
BILLING_EXCHANGE_RATES={"USD":"7.2","EUR":"7.8"}
```

- 未指定新汇率表时，兼容旧变量 `MODEL_BILLING_USD_TO_CNY_RATE` 并映射为 USD 条目；新表存在时以新表为准，`{}` 表示不启用外币换算。
- 不自动提供默认外币汇率。非法币种、非正数或无效 JSON 在启动时被拒绝。
- CNY 无需配置汇率，恒为 1；提供商返回的 RMB 按 CNY 处理。配置表使用 CNY，不使用 RMB 别名。
- `setConfig({ billing: ... })` 整体替换汇率配置，已删除的币种不会因合并残留；后续结算读取当前配置，既有账本汇率和金额不会重算。
- 缺少汇率、原币金额缺失或未计价时，保留原始费用事实但无法人民币结算，不把它当作零费用。只有明确免费规则才按免费处理。

公共换算函数 `convertToSettlementCurrency` 位于 `server-core`；模型网关与用量账本通过现有 `settleChargeToCny` 包装调用，积分换算继续使用租户的 CNY/积分规则。扩展结算币种需要同时调整积分政策，不能只更换货币代码。

## 额度边界

2026-10-30 首发决策：不要求严格不透支。调用前继续校验会员有效期、允许模型和剩余额度；调用后根据真实费用幂等记账。已开始及并发中的调用允许产生超额，既有会员账本使用 `excessPoints` 记录，余额耗尽后拒绝后续调用。此语义不等于允许无限制消费，也不承诺金额严格封顶。

本期撤下单次最大成本估算、App 金额预留表及其调用钩子，不要求模型插件提供预算准入接口，初始化不依赖可计算的最大调用价格。移除依赖预留机制的 `appCreditLimits` 配置，旧配置携带该字段会被拒绝；多个 App 共用账号的会员额度。

现有流水线 Token 预算、运行并发控制和存储限额保持各自职责。服务账号替用户初始化产生的用量仍归属经过验证的受益账号，不能借此改变请求权限。超时、取消或缺少用量不自动代表免费；排查时应区分提供商错误、未计价、缺少汇率、会员过期与余额耗尽。
