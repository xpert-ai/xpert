## 场景

- A 是新建的 `AI_BUILDER` 用户，B 是新建的 `VIEWER` 用户；两者均非管理员。
- A 在“测试组织”创建私有 `XpertWorkspace`，成员列表为空。
- A 创建并发布 `workspaceDataScope=shared` 的 Assistant，绑定一个仅包含 B 的用户组。
- B 通过用户组获得 Assistant 使用权，没有创作工作区成员资格。
- 另建用户隔离 Assistant、同工作区未授权 Assistant 和未发布草稿，验证权限边界。
- 管理员仅用于创建测试账号、组织成员和用户组；文件操作均使用 A、B 各自的登录或 B 的委托会话。

## 实测发现并修复的额外问题

两个真实控制器同时注册了 `GET /ai/conversations/:conversationId/files`：
文件理解模块将其作为 FileAsset 附件列表，Workbench 则试图将其作为运行目录列表。
本地实际命中前者，返回空附件数组，即使同一文件可以通过单文件接口读取。

修正为：

- FileAsset 附件列表继续使用 `/ai/conversations/:id/files`。
- Workbench 文件目录和操作使用 `/ai/conversations/:id/workspace/*`。
- 保留不冲突的旧单文件读取、保存、下载、上传和删除路径。
- `xpert-sdk-js` 的 Workbench 客户端同步采用新路径；发布时需同步交付该 SDK 更新。
- 新增两个控制器共同运行的 HTTP 回归测试，覆盖两种注册顺序，避免孤立控制器测试遗漏路由冲突。
