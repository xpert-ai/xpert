## 结论与阻塞修复

公共组件继续消费配置、投影和显式执行身份，没有引入 BOM / Code Review 文案、业务 key 判断或业务路由。历史业务状态仍来自所选轮次快照，执行圆点单独表达实际执行结果。

| 级别 | 问题与触发条件                                                                                                                                                                     | 修复及证据                                                                                                                                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P2   | 实际执行成功，但 Task 业务状态为 failed 或验收结果为 rejected 时，执行圆点仍显示失败；有 Invocation 状态时，UI 又优先使用可能过时的 native runtimeStatus，与第五批服务端口径不一致 | 公共执行摘要优先采用 invocationStatus，再读 runtimeStatus，最后兼容旧 Task 状态。圆点颜色只由该执行状态决定，业务拒绝仍作为独立注释。回归覆盖 Invocation 成功覆盖旧 running、waiting、真实运行失败，以及执行成功但业务拒绝的绿色圆点和对应执行点击 |
| P2   | 从深链接或保存的视图位置进入已有实例后，轮询回调保留初次 loaded=false，每次重读流水线目录第一页，导致用户刚加载的后续选择项消失                                                    | 用 ref 保存目录首次加载完成状态，轮询只更新实例图和轮次；显式刷新仍可重读目录。交互回归验证加载第二页后经过轮询，第二页仍保留且目录没有被额外请求                                                                                                  |

原则注释仅解释执行结果与业务验收分离、轮询闭包与目录就绪状态，不逐行描述实现。

## 已复核的公共交互边界

| 范围           | 复核结论与证据                                                                                                                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 配置标签       | 阶段、节点和分支展示配置提供的 label / title。分支标签按字符换行，布局为标签分配空间；不以英文条件 key 替代业务文案，不在组件内翻译 BOM 条件。中性测试配置中的长中文标签逐字符完整保留                                    |
| 阶段图标       | 阶段配置的 icon 从公共允许列表解析，阶段表头与工作节点使用同一配置，缺省使用通用图标；控制节点保持类型图标。真实 Lucide 渲染回归覆盖 code 和 shield-check，公共组件无业务图标映射                                         |
| 控制节点布局   | 控制节点在绘图阶段寻找相邻工作节点泳道，不新增“流程控制”泳道；绘图位置不回写节点业务归属。先计算控制节点位置再筛选泳道。已有布局回归及新增组件回归覆盖同泳道控制、混合阶段和长分支标签                                    |
| 节点执行圆点   | 节点必须显式提供 executionIds，并与本节点 taskIds 同时匹配；未提供或空数组均不按 Task、Assistant 或时间猜测。节点卡片不重复展示 Agent，仅显示本节点执行圆点                                                               |
| 泳道汇总与点击 | 节点与泳道复用去重函数，依次按 native、Invocation、attempt 身份去重。点击传递被展示的 taskExecutionId，不跳到最近执行。回归覆盖同一 native 的多个引用、当前与旧轮次切换、兄弟节点不借用记录，以及点击圆点不误打开节点详情 |
| 节点详情       | 概览、执行记录、证据版本分栏；轮询不重建详情身份，切换节点或轮次重新定位。已有回归覆盖连续 30 次轮询后工作台入口仍唯一、分栏状态保留、历史轮次移除业务工作台操作。详情执行列表复用同一归属与去重函数                      |
| 配置入口       | 配置弹窗默认关闭，只有配置按钮或显式 configure 意图打开；保存的视图状态不持久化弹窗打开状态。新增回归验证按钮打开、关闭后重新渲染仍关闭，而且只查看弹窗不提交配置；配置可管理性仍由服务端返回                             |

这些 UI 检查不代替 API 授权：执行详情的最终可访问性仍由宿主及服务端校验。本轮没有放宽权限、修改执行归属、变更历史快照或扩展公共协议。
