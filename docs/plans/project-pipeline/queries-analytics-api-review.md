## 结论与阻塞修复

公共层继续按持久化身份和作用域处理查询，没有增加 BOM、Code Review、业务名称或文案判断。业务快照与运行时观察分开：读取可更新响应中的执行状态，不回写历史节点或 Task 的业务状态。

| 级别 | 问题与触发条件                                                                                                             | 修复原则与回归证据                                                                                                                                                                                                              |
| ---- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1   | 泳道已经按节点、轮次分配执行，但项目与跨项目统计仍仅按 Task 关联选取，缺少归属证据的旧记录也能进入成功率、耗时和执行数量   | 统计在同一 MVCC 事务中读取 Operation / 已消费 native grant，复用泳道的精确归属规则；再按 native / Invocation / attempt 身份去重。数据库用例验证旧轮次保留、当前轮次不带入旧执行、无归属记录不计入、同一执行的两条引用只统计一次 |
| P2   | 同一 Task 的多个节点关联同时被查询时，Invocation 观察取第一个 Task Link，可能把有有效关联的执行判为未知                    | 按 Invocation 内保存的 nodeInstanceId 与 taskId 精确匹配；仍保留项目、operation / callId 等校验。回归同时提供两个节点的 Invocation 和关联，反转关联顺序后两者均正确显示成功                                                     |
| P2   | Invocation 的完整状态已有 waiting / unknown，但统计读取兼容用 Task 状态，将其误计为 running / queued                       | 优先使用 invocationStatus，再使用原生 runtimeStatus，均缺失才回退旧 Task 状态。等待、未知及取消中的请求不被计为成功、失败或已取消；成功终态覆盖旧 running 观察                                                                  |
| P2   | 历史轮次已经合并最新执行观察，当前轮次仍直接使用 Provider 投影中的 runtime，导致执行成功而节点及当前业务运行数量仍为运行中 | 当前、历史图和统计统一使用只读运行时合并；只合并本节点、本轮次已归属的执行，且要求完整 Task 覆盖。数据库用例验证当前节点成功、统计运行数归零、旧业务状态保持、数据库中原 runtime 快照未被改写                                   |

重要注释说明归属证据优先、兼容回退、完整 Invocation 状态优先以及只读观察边界，不解释逐行实现。

## 已复核的隔离与兼容性

- HTTP 图、轮次和统计接口使用 Project Guard；查询服务再次检查可读项目。请求中的 tenantId、organizationId、actor 等覆盖字段被严格 schema 拒绝，范围来自认证上下文。
- Project 和 Agent Workbench View 使用宿主已解析的 project / runtimeScope，而不是 UI 传入项目。新增回归覆盖两种宿主、伪造范围字段和缺少 runtimeScope。
- 图与历史轮次按租户、组织、项目、实例和 run/round 关系查找；即使上层测试 ACL 被刻意放宽，跨范围读取仍得不到目标图或执行统计。native grant 的归属读取另有未消费、软删除、空组织及跨实例隔离测试。
- 跨项目报表先在事务中确认全部所选项目可读，再读取数据；无权项目不会被静默省略。原有数据库回归覆盖成员移除、软删除和不同 actor；HTTP 回归覆盖拒绝 Assistant 委托凭据扩大管理报表范围。
- 执行详情仍定位到被点击的 taskExecutionId，校验对应 Invocation / 节点关联或真实会话和消息执行祖先；不会取“最近一次”执行。绑定失效、执行不可访问等情况继续保守拒绝，没有放宽授权。
- 业务状态来自所选轮次快照；后续实际执行终态只影响响应的 runtime。新轮次复用 Task 不会改变旧轮次的任务状态，也不会凭时间、序号、Assistant 推断执行归属。已有执行身份不可重绑的写入约束保持不变。
- 统计执行窗口仍为实际开始时间的左闭右开区间；没有开始时间的记录不制造零耗时。跨实例 / 项目汇总从原始执行事实重新计算，不相加成功率或百分位数。
- 未改变 HTTP 响应 schema、数据库结构或插件执行接口。纯 Contracts 统计 helper 新增可选 executionIds，旧调用方未传时保留原 Task 关联语义；平台查询始终提供显式数组，空数组意味着没有已归属执行。invocationStatus 也是已有执行视图字段，统计 Fact 类型仅补充读取能力。

兼容性影响：旧记录若没有持久化执行归属，项目报表的 recordedAttempts 可能比旧版减少，这是排除无依据归属后的口径修正，不是删除执行记录。历史执行仍保留于 Task 存储，不能通过猜测轮次自动补入报表。
