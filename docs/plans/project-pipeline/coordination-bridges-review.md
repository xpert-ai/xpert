## 已复核并保留的行为

- SQL 事务先写入 Operation / Provider Action 和稳定身份；队列投递在事务外，可从 SQL 重建。外部执行不放入数据库事务。
- 领取、派发和结算检查作用域、原始 actor、worker owner、递增 fence 及数据库租约时间。迟到 worker 不能写回覆盖接管者；Task / Node 投影失败会回滚同一事务的结算。
- 响应丢失和未知结果只观察原 receipt / execution / Invocation；不把超时当成业务失败，也不自动发起第二次执行。旧轮次的执行结果可以继续观察，但不能推进旧业务结果或新一轮。
- 原生 grant 分为“准备精确执行身份”和“一次性消费”。已经准备的 grant 允许晚于原 worker 租约消费；这不是重新领取执行权。消费仍检查项目权限、Assistant 使用权、发布版本、当前节点及轮次、输入摘要、执行身份和是否已消费。回收后的观察租约不能准备新 grant。
- 非 `unknown` 回执缺少必填 `receiptKey` 会被共享 schema 拒绝，原回执不变；`unknown` 可以省略标识，此时保留已有句柄。最初对此处的怀疑在协议校验回归中排除，没有扩大生产代码改动。
- 原生执行成功与业务验收成功继续分离。输出采集或证据验证暂时不可用时，保留执行事实并重试只读采集，不重复执行。

SQL 与外部系统之间没有跨系统事务，因此本方案不承诺外部副作用“恰好一次”。在授权消费或派发标记之后、外部系统确认之前崩溃，可能长期保留未知状态；必须依赖执行方提供可查询身份或人工核对，不能盲目重发。
