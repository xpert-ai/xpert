## 已复核的接入边界

- Cloud `/project/:id/pipelines` 仅设置流水线初始视图及校验后的 instance / round / node 焦点，不自动打开配置；`/timeline` 仍承载项目任务。返回流水线时不会把 URL 的 configure 字符串解释为配置动作。
- `project.application` 只传项目和可选节点身份；入口重新读取已授权项目分类，再由 type-entry 解析业务 View。被撤销、无法解析、项目不匹配或导航取消时保留错误，不退回其他业务工作台。`navigateProjectEntry` 保留 Project 路径与服务端返回的 selection / parameters。
- Project 中的 Invocation / coding 执行结果仅进入允许的公共结果 View，携带精确 selectionId 和当前项目；会话执行携带原 executionId，不改为最近执行。组件销毁时注销命令处理器，异步会话查询返回后再次确认上下文。
- Cloud 视图偏好按 host、View、用户和 runtimeScope 隔离，仅允许有数量与长度限制的标量。iframe 消息仍校验来源窗口、实例和已提供的 scopeRevision；偏好只影响 UI，不参与 API 授权。
- Desktop 的独立项目入口只打开配置的平台地址，使用平台登录，不把 Assistant secret 或账号令牌拼入 URL。应用和流水线目标仅接受已知路径与合法焦点身份，不接受任意重定向地址。
- Desktop 恢复的 projectId 来自授权 conversation 解析；本地保存值不作为授权来源，也不持久化临时 secret。恢复 ChatKit 时携带项目并锁定项目选择；会话无权或已删除时按既有规则退回新会话，临时错误不清除保存位置。
- Desktop 原生执行打开与当前项目结果 View 的内部切换依赖 ChatKit 的公共导航协议；其源码中执行目标先尝试精确执行查看，再按既有兼容协议委托宿主。本轮验证了宿主导航及恢复边界，没有修改 ChatKit 或声称完成其安装版本的新增原生端到端验收。

兼容性：公共导航和 API 协议不变。原先匿名 key 下保存的 UI 偏好不自动迁移到某个账号，避免认错归属；首次进入会重新选择视图，业务数据不受影响。其他尚未传 runtimeUserId 的 Cloud 远程宿主仍可使用组件，但不再持久化匿名偏好。
