# 插件滚动重启与失败恢复

插件变更的数据库配置表示期望状态；预安装成功不代表所有 API 副本已加载成功。安装、更新或卸载后的收敛结果继续使用 runtime control 的 generation 和 restart 状态接口。

## 副本选择与流量保护

- 历史成员仍保留用于审计；新操作只选择心跳有效、bootId 一致且就绪检查未过期的副本。旧容器记录不会再阻塞新的操作。
- 本轮目标一旦确定，运行中的目标失联仍会使本轮失败，不会通过删掉目标伪装成功。
- 返回的旧副本必须核对持久化的期望插件版本和 runtime revision。未通过时 `/api/health/ready` 返回 503，业务请求也返回 503。
- 每次只排空一个候选副本。替换进程完成监听、插件状态匹配且连续就绪至少 3 秒后，才确认并继续下一个副本。
- 自动操作在排空前、发出终止信号前均要求仍有其他健康副本；单副本及集群退化到只剩一个健康副本时也适用。没有容量时保持服务在线，本轮到期后报失败。失败会终止本轮和后续排队的变更，不会自动反复重试失败的 generation。
- 单副本维护需要 Default tenant 的交互式 SuperAdmin 在 `POST /api/system/runtime/restart` 中显式传入 `confirmation: "RESTART"` 和 `allowDowntime: true`。该许可允许服务中断，不会传递给后续自动插件变更；省略或传入 `false` 都继续保护最后一个健康副本。
- 每个 generation 在发布时原子保存完整期望插件快照。本轮被安排重启的替换进程按该快照接流量，后续排队变更不会阻塞本轮；未参与本轮的新增或返回进程仍须匹配最新期望配置。历史操作缺少快照时不放宽校验。
- 负载均衡器应使用 `/api/health/ready` 摘除未就绪副本；业务 503 只是兜底，不替代正确的流量路由。Redis 租约或状态核对过期时也会关闭就绪状态。

## 启动日志与期限

`plugin.startup.started/completed/failed` 记录插件、阶段、耗时及失败代码，覆盖 import、register 和 onPluginBootstrap。异常原文和配置不会被这些新增日志输出。容器创建和监听阶段也记录在本地启动状态中。

异步插件步骤的期限为 30 秒；整个 API 启动和就绪期限为 120 秒。独立看门狗线程在主线程被同步初始化或 CPU 死循环占住时仍会写出 `runtime.startup.timeout`，然后终止该候选进程。PM2 等外部进程管理器负责重新启动。重启协调器给每个候选 300 秒，包含排空、失败启动和恢复启动；失败时其他候选不会继续排空。

## 上一份可用配置

每个副本在 `<serverRoot>/plugins/.runtime-plugin-state/<replica-hash>.json` 保存自己的启动记录。文件权限为 0600，配置使用现有插件加密机制保存；目录应随插件数据持久化。副本标识来自 `XPERT_INSTANCE_ID`、`HOSTNAME` 或主机名，多个进程必须使用不同且稳定的标识。

候选启动未被接纳时，下次进程启动会尝试上一份已接纳配置。恢复时核对实际插件版本和 runtime revision，匹配后且本轮已经失败，才重新接流量。恢复不会修改数据库中的期望安装配置或回滚业务数据。

如果没有可用快照，或恢复也失败，进程输出 `runtime.startup.recovery-required` 并保持不可用，等待运维修复，不继续制造 PM2 崩溃循环。修复包、依赖或配置后，可通过健康 API 显式重试生成新的 generation；已恢复且健康的副本会在排空前解除本地候选阻止状态。停留在 recovery-required 的副本需由运维修复后重新启动；若修复不改变配置指纹，先备份启动记录，再仅清除 attempted、blocked、recovering 字段，保留 good 和 goodRuntime。

旧包及依赖必须仍可用；不完整的包、无法重装的依赖、破坏性的数据库迁移无法靠配置快照恢复。插件与 API 仍共用进程和部分基础设施，本次保护限制滚动更新的影响范围，并未实现插件独立进程隔离。
