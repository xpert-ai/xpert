---
title: '事件收件箱'
description: '从 Assistant 工作台或 Bosi 的个人入口查看事件、核对处理结果，并打开关联会话。'
---

事件收件箱（Event Inbox）记录 Assistant 从已接入的插件收到的业务事件。每条事件有一个回执。例如，供应商重新报价后，你可以从回执查看交期是否推迟、产生了哪条风险，以及这次报价是在哪个会话里解析的。

## 从哪里打开

先登录并选择组织。三个入口使用同一个内置视图，同一事件的回执 ID 和处理状态在各入口一致。

| 入口             | 路径                                                           | 可见范围                                                           |
| ---------------- | -------------------------------------------------------------- | ------------------------------------------------------------------ |
| Assistant 工作台 | 打开目标 Assistant，在工作台菜单选择 **事件收件箱**            | 固定为这个 Assistant 下与你关联的事件                              |
| Bosi Web         | 左侧 **Bosi Agent → 我的事件**，页面路径为 `/chat/event-inbox` | 当前组织内，你有权查看的各个 Assistant 的事件，可按 Assistant 筛选 |
| Bosi App         | 在用户菜单中选择 **我的事件**                                  | 与 Web 个人入口相同，可以直接打开，无需先选 Assistant              |

平台按当前租户、组织和**事件绑定的执行用户**筛选回执，再检查你能否访问已发布的 Assistant、是否有其工作区的创作权限，以及绑定项目时该项目与 Assistant 的访问关系。因此，同一组织的两位成员可能看到不同的事件。个人入口的“全部”只包含你的可见范围。分类计数、搜索、详情和重试都遵守这个范围。

## 找到一条事件

1. 在左栏选分类，例如 **采购事件**。中栏按收件时间从新到旧列出事件。行内的图标和名称表示具体类型，例如“报价修订”；飞书消息下则有“飞书入站消息”和“卡片操作”两种类型。
2. 用搜索框查找类型名称、业务对象引用、来源事件 ID 或回执 ID。插件支持标题搜索时，也可以按事项标题查找。在个人入口可叠加 Assistant 筛选。选择 **需关注** 可集中查看“已阻止”和“已隔离”的回执。
3. 选中一行，在右栏查看发生时间、收件时间、处理结果或原因。插件提供结果时，可展开查看业务字段；展开 **技术详情** 可取得排查所需的回执 ID。窄屏上可从详情返回原列表。

缺少对应版本的类型说明或来源插件已卸载时，仍然有权查看的历史回执归入 **未分类**，显示原始类型键。列表为空时，先核对当前组织、Assistant 和筛选条件，再确认该来源是否已为这个 Assistant 启用收件。打开详情不会改变事件的处理状态。

## 核对处理结果

| 状态            | 如何理解或处理                                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 待处理 / 处理中 | 平台已收件，正在排队或由后台处理。可以刷新查看进度。                                                                                  |
| 等待重试        | 本次后台处理未完成，平台将在退避后重试。                                                                                              |
| 已处理          | 插件已记录业务操作及其结果引用。代码评审是否完成、飞书卡片是否送达，还要查看对应的运行或渠道记录。                                    |
| 已忽略          | 插件按业务规则结束了处理。例如，首份报价只建立比较基线。                                                                              |
| 已阻止          | 查看原因。授权已变更、卡片操作者不匹配或交期无法判定，都可能阻止处理。                                                                |
| 已隔离          | 排查原因后，若详情出现 **重新尝试**，确认后原回执会重新排队。只有绑定仍启用、修订仍匹配、来源支持该类型版本且尚无终态决定时才可操作。 |

## 打开会话

选中事件，在详情点击 **打开会话** 即可进入关联的聊天线程。三个入口都使用同一个动作。插件须提供这条事件对应的会话，平台再核验当前用户的会话读取权限、租户、组织、已发布 Assistant 版本族和适用的项目范围，并确认会话已有线程。点击时宿主会按回执 ID 重新查询；如果此时权限已变更，可刷新详情查看最新状态。

| 事件        | 按钮打开哪个会话                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------- |
| Code Review | PR 自动化运行所关联的可读评审会话，或该次工作流诊断的会话。等待评审创建会话时，详情可以先显示运行结果。 |
| 采购比价    | 解析**这一次报价修订**的来源会话。历史修订若没有保存来源会话，仍可查看回执及可用的风险结果。            |
| 飞书        | 与该条消息或卡片派发明确关联的 Xpert 会话。新会话可通过同一次 Handoff 的成功出站记录建立关联。          |

来源没有明确关联、会话尚无可用线程，或当前用户无权读取时，详情会隐藏按钮。例如，知道飞书群号或者拥有采购案例编号，都不足以从回执打开某个聊天线程。
