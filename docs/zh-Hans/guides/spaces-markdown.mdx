Markdown 编辑器是独立的 Remote View 插件，使用 Tiptap 与 Yjs。空间列表负责找到文档，ChatKit Workbench 负责打开编辑标签；编辑器内只保留文档编辑功能，不重复显示空间导航栏。

本文适用于[协作空间](/zh-Hans/guides/spaces)及配套的当前编辑器实现。部署依赖与验证边界见[发布与部署](/zh-Hans/architecture/spaces-content#发布与部署)。

## 文档工作区

- 左上角的标题下拉菜单用于切换当前项目中的已注册 Markdown 页面，选择器支持搜索和分页。
- 顶部提供格式、插入、撤销和重做操作；历史、审阅及分享相关操作委托给 ChatKit 或 Assistant。
- 文本块左侧的六点按钮打开块菜单，可转换块类型、在下方插入、复制块链接或删除该块。
- 复制文档或块链接需要宿主配置公开入口地址；链接保留资源和块标识，不带当前私有会话或访问凭据。打开链接仍需授权。
- 编辑器报告未保存状态。切换文档、关闭标签或离开工作区时，ChatKit 等待保存确认；保存失败会保留当前编辑器。

## 插入菜单

顶部插入按钮和块菜单使用统一的插入能力。支持的顶层段落内输入 `/` 可搜索菜单，并使用键盘选择；代码块和 URL 中不会触发。菜单处理输入法组合状态，避免中文输入被当作快捷指令。

| 分类           | 当前能力                                    | 保存形式或操作                             |
| -------------- | ------------------------------------------- | ------------------------------------------ |
| 基本内容       | 段落、一至三级标题、无序/有序列表、任务清单 | 标准 Markdown                              |
| 格式块         | 引用、代码块、水平分隔线                    | 标准 Markdown                              |
| 表格           | 插入及编辑受约束的表格                      | GFM 表格                                   |
| 数学公式       | 行内公式、独立公式块                        | LaTeX 与 `$` / `$$` 定界符                 |
| 提示与强调     | 预设的引用块内容                            | 可移植的引用块，不注册新的 AI 指令         |
| 页面           | 新建子页面、引用已有页面                    | 独立页面资源及资源链接                     |
| 图像           | 上传或选择当前项目中的图片                  | 授权资源引用                               |
| 文件           | 上传或引用当前项目中的附件                  | 授权资源引用及下载入口                     |
| 链接           | 添加外部链接或页面链接                      | 外部链接限定为允许的协议；页面使用资源标识 |
| 交给 Assistant | 将当前文档或选区作为上下文                  | 不自动发送消息，不覆盖已有输入草稿         |

块级插入定位到当前顶层块之后，不用新内容覆盖选中的正文。菜单打开后即使协作内容变化，也会重新检查插入锚点；锚点消失时提示重新选择位置。

聊天引用、交互式可视化、在编辑器中直接生成图片，以及任意外部应用嵌入不属于当前插入菜单能力。AI 生成和通用审阅仍由 Assistant 承担。

## 表格与 Markdown 范围

支持段落、标题、强调、链接、嵌套列表、任务清单、引用、代码、分隔线、受约束表格、公式和授权图片。表格最多 30 列、200 行，使用一个表头行；单元格限单行段落，不支持合并单元格、嵌套块、列宽及不一致的列对齐方式。前端和服务端都检查这些约束。

Markdown 正文上限为 1 MiB。原始 HTML 和任意外部图片 URL 不在支持范围内，校验失败不会覆盖原文件。首次注册保留文件字节；后续编辑按支持的 Markdown 模型序列化，不承诺任意 Markdown 的逐字节往返一致。

## 公式

1. 在插入菜单选择行内公式或公式块。
2. 输入 LaTeX，查看本地 KaTeX 预览；输入框内不需要再包裹 `$` 或 `$$`。
3. 确认后插入公式。再次编辑时可以修改或删除。

每个公式最多 4,096 个字符，每份文档最多 200 个公式；行内公式不接受换行。普通文本中的字面量 `$` 会按文本处理或转义，代码中的内容不作为公式解析。

公式使用稳定标识。确认修改前会核对该公式及原始 LaTeX，若其他成员已修改或删除它，旧弹窗不会覆盖新的内容。KaTeX 和字体随插件打包，关闭受信任 HTML 功能，并限制展开次数和尺寸。

## 子页面

子页面是一份独立 Markdown 文件与独立资源，不是嵌入父页面的一段正文。

- 从父页面创建时，文件默认放在父页面所在的物理文件夹。
- `parentPageId` 表示页面层级，`parentId` 表示文件夹位置，两者相互独立。
- 重试相同创建请求不会重复创建子页面；同名页面也不会覆盖已有文件。
- 页面层级最多 32 层；当前层级查询最多返回 100 个直接子页面，并说明是否还有更多。
- 重命名或移动父页面文件不自动重命名或移动子页面。
- 父页面移入回收站不会级联删除子页面；子页面仍可从空间访问，失效的父级入口被隐藏，父页面恢复后可重新关联。
- 移动物理文件夹仍会移动其中的实际文件，这与页面父子关系是两回事。

当前没有子树复制、批量重设父页面或完整层级离线导出。单独导出的 Markdown 正文不包含数据库中的父子关系。

## 图片、附件与页面引用

引用保存为稳定资源 URI，而不是临时下载地址：

```text
xpert-resource://v1/{kind}/{providerKey}/{resourceId}
```

`kind` 为 `image`、`file` 或 `page`。当前 Spaces 适配器限定同一项目，打开时同时检查包含引用的文档与目标资源权限。文件移动、重命名后引用仍有效；目标被移入回收站或权限撤销后显示不可用，恢复权限或资源后可再次解析。

图片支持 PNG、JPEG、GIF、WebP，并验证文件内容；不接受 SVG 或 HTML 作为图片。上传文件上限为 25 MiB。临时预览地址只存在于浏览器运行时，不写入 Markdown 或 Yjs。

若上传成功后插入位置已被其他成员删除，文件仍保存在项目中，界面会提示未能插入，可重新选择该文件。下载附件会再次鉴权。Markdown 导出中的资源 URI 需要 Xpert 授权环境解析，当前不打包离线附件。

## 实时协作与保存

同一项目资源通过不同 Assistant 打开时进入同一个协作文档。编辑器通过 Yjs 合并修改，显示在线成员与光标。服务端持久化接受的更新后再广播，并分别核对接收者权限。

需要区分两个状态：

| 状态           | 含义                                            |
| -------------- | ----------------------------------------------- |
| 协作更新已接受 | 服务端已保存该次 Yjs 更新，可以继续合并与分发   |
| 文件已保存     | Markdown 文件、已发布版本和接受的更新序号已一致 |

收到协作更新确认不等于文件已保存。文件发布失败时保留待保存状态，不提前报告成功。断线后会利用状态向量补齐缺失更新并重试当前窗口队列；当前没有关闭浏览器后仍可恢复的持久离线草稿队列。

恢复版本或升级模型会更新协作 epoch，旧会话的写入被拒绝并需要重新加载。页面刷新或关闭时，浏览器的未保存提示只提供离开保护，不等于离线备份。

## 审阅、版本与外部修改

AI 修改提案、评论、历史版本和外部修改冲突由 ChatKit 中的 Assistant 审阅入口处理。编辑器提供文档上下文、选区和保存状态，不内置第二套通用审阅系统。

接受提案、恢复版本或处理冲突时，服务端检查版本、hash 或协作序号等基线，拒绝过期操作。恢复前也需确认当前编辑已经保存。

受管理文档不能通过普通文件写入接口绕过文档发布流程。若 sandbox 或其他外部进程直接改变文件，系统检测冲突，保留外部版本并停止自动覆盖；用户再选择采用文件版本或文档版本。这是冲突检测与保留机制，不代表 sandbox 文件系统已被设为只读。

实现与接口边界见[内容平台架构](/zh-Hans/architecture/spaces-content)。
