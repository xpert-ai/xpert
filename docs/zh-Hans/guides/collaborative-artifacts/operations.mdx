协作成果由平台、宿主、数据服务和插件共同提供。部署时需要配套的接口与格式支持；只更新编辑器不能补齐服务端权限、持久协议或宿主草稿能力。

## 组件与部署顺序

| 组件                           | 维护职责                                                      |
| ------------------------------ | ------------------------------------------------------------- |
| Xpert 平台                     | 资源身份、Project 授权、协作会话、Artifact 版本与委托生命周期 |
| ChatKit 与宿主                 | 视图生命周期、上下文、未保存保护及受控本地草稿存储            |
| Canvas / Office Editor         | 各自的领域模型、唯一写入服务、编辑器与 Agent 适配             |
| Live Dashboard 与来源 Provider | 查询契约、来源授权、结果复用和分析证据                        |
| Data Xpert 与 RDF 服务         | 指标定义、认证历史、持久投影任务和本体投影                    |
| Motion 与 Sandbox Runtime      | 配音任务、受控视频渲染、导出文件和任务结算                    |

公开 SDK/ChatKit 使用消费者锁文件中的正式版本；内部 contracts 与 plugin-sdk 按目标平台版本构建。开发未发布接口时的临时源码链接不能作为正式包部署依据。

先准备兼容的服务端 reader 和迁移，再更新 writer、插件与宿主。旧工作簿保持可读，使用受控结构操作时才升级格式；不要批量静默改写用户文件。服务端渲染还需要匹配的 Runtime Binding 与工作队列，普通进程启动成功不能替代执行控制能力。

## 数据迁移与文件归属

Data Xpert 的认证迁移分别保存定义证明、认证事件和投影 outbox。指标变更、认证历史与 outbox 同事务提交；投影失败后使用持久任务继续处理，不伪造人工认证历史。

原生工作簿的数据库 head、快照和操作日志是权威状态，Project 文件是可重建投影。Content Catalog 中的 `writeOwnership: provider` 阻止普通文件上传、覆盖、删除和递归目录操作绕开原生 writer。

已有工作簿目录记录使用 Office Editor 随包迁移 `migrations/20261112-workbook-write-ownership.sql` 回填归属。执行前暂停写入并备份；脚本包含事务、锁及明确的 provider/model/Project/path 校验，覆盖归档资源，可重复执行。异常元数据会中止整批处理，应通过 Provider 修复后再继续，不按文件名猜测归属。

## 备份哪些内容

- **平台数据库**：工作簿 head、快照、操作日志、资源和授权记录。
- **Project 文件**：不可变投影、文档、附件、证据及导出文件，连同路径、权限模式和字节摘要。
- **Data Xpert 数据库**：指标、认证历史、outbox 与迁移状态。
- **RDF 数据集**：通过一致性导出保留本体投影，不能直接复制运行中的 TDB2 目录代替事务快照。

建立恢复点时冻结相关写入，等待事务和投影达到可解释状态，保存组件版本及各份备份的时间和摘要。无法同时冻结各服务时，明确各自时间边界与可重放事件，不能声称获得跨服务原子快照。备份使用私有存储，不放入源码仓库。

工作簿原生备份只保存模型内容，不能替代数据库、文件、权限及历史的系统备份。

## 故障恢复

1. 保留故障记录，停止相关写入和投影任务。使用独立实例、数据库、卷和网络准备恢复副本。
2. 恢复数据库、Project 文件和 RDF，核对 head 对应快照、文件摘要及请求回执，再启动兼容服务。
3. 数据库已提交但投影缺失时，由获授权的 Provider 从权威快照修复；损坏字节先隔离，再按当前摘要比较后替换。修复不创建业务版本。
4. 保存结果不确定时重试原请求 ID。数据库提交前失败保持旧 head；已提交但丢回执时返回原提交，不重复增版。
5. 恢复正常权限检查和受管读取后再开放写入，保留上一恢复点和故障记录。

不要从较旧文件反向覆盖数据库 head，也不要通过删除历史、outbox 或扩大权限来绕过异常。

## 兼容回退

Canvas 或工作簿写入新 schema 后，旧 writer 不能直接接管。优先冻结新功能、保留兼容 reader；需要数据回退时，使用核对过的完整恢复点，或显式导出可兼容内容。不能安全转换的特性保持只读，不删除身份元数据或未知扩展。

认证 down 迁移在存在已使用的 revision、认证证据、历史或 outbox 时拒绝删除。该保护不能通过清空业务表绕过。

## 运行信号与处理

| 信号                       | 处理                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| `409` 或同格、结构冲突     | 保留草稿，读取新基准并形成新意图                                 |
| `503 office.workbook_busy` | 写入队列已满，保留原请求并延迟重试；检查负载和事务，不扩大权限   |
| 协作连接断开或队列溢出     | 重连从持久状态补齐；通知合并不代表丢弃已提交操作                 |
| 投影摘要不符               | 隔离损坏副本，经 Provider 重新授权后修复                         |
| 认证失效或 `sourceChanged` | 停止旧来源消费，重新认证后显式采集新证据                         |
| 配音或渲染任务失败         | 根据原任务状态处理；渲染重试复用音频，不自动重复不确定计费的合成 |

工作簿在获取数据库连接前排队：每个 DataSource 最多两个活动事务，每文档串行，最多 64 个等待请求、32 MiB 意图。跨进程仍使用数据库行锁和实时授权。协作连接合并短暂的 revision/presence 通知；持久 Yjs 更新队列上限为 64 条、2 MiB，溢出断开后重新同步。

这些是实现限制，不是吞吐或延迟承诺。浏览器草稿、历史合并及格式限制见 [Sheets 协作](./sheets)。
