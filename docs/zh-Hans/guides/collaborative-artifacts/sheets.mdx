原生 Sheets 使用 Xpert 的工作簿模型、操作协议和版本历史。Univer 提供网格界面与公式计算；人和 Agent 通过同一个服务端写入入口提交，协作不依赖 Univer Pro。

## 打开与保存

从项目 Spaces 新建或打开原生工作簿，也可通过聊天资源卡片打开已有工作簿。普通上传的 XLSX 文件仍是文件资源；编辑文件不会自动把它变成原生协作工作簿。

1. 在网格中编辑值或公式。未保存内容属于当前草稿。
2. 点击“保存”提交本次意图。成功回执确定服务端版本。
3. 其他成员通过协作连接收到版本通知，并读取已提交变化；未保存草稿不会被直接覆盖。

服务端按工作簿序列化提交，检查当前权限和基准版本。每次提交有稳定请求 ID：重试相同意图不会重复增版；不同意图不能复用同一 ID。Agent 的 `office_excel_read` / `office_excel_edit` 使用相同资源和提交约束。

## 并发与冲突

| 情况                                     | 处理方式                             |
| ---------------------------------------- | ------------------------------------ |
| 同基准修改不同单元格                     | 在支持的历史窗口内合并，保留各方修改 |
| 同格竞争，或单元格改动后又改回           | 拒绝过期提交，保留草稿供重新处理     |
| 原生编辑器的结构命令、完整替换或历史恢复 | 形成新的结构基准，旧坐标不能直接重放 |
| 基准落后超过 100 个版本                  | 重新读取完整状态，不能无限追溯合并   |
| 成员被撤权                               | 后续读写、历史、同步和导出拒绝       |

出现冲突时先保留本地内容，再读取最新版本并决定需要重新应用的修改。不要将冲突统一当成网络错误重复发送，也不要通过新建同名工作簿绕过冲突。

## 行列结构与公式

使用“行、列和工作表”菜单执行受控结构操作。首次成功提交会升级该工作簿的结构协议，保留旧历史的可读性。工作簿使用稳定行列身份，使支持范围内的旧单元格修改可以跟随原行列，而不误写到插入后的邻近位置。

支持插入和删除行列、工作表改名、整行重排/排序、合并与取消合并。删除的目标、同格竞争、并发结构修改或无法确定的引用会拒绝整次操作。

| 能力                     | 边界                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| 公式引用变换             | 支持 A1、绝对/混合引用、矩形区域、整行/列范围及带引号的 Unicode 工作表名 |
| 整行排序                 | 按输入值排序，空值始终置后；公式排序键被拒绝，不用过期计算缓存代替输入   |
| 非连续范围               | 重排后无法保持连续的引用范围会拒绝，不扩展到无关单元格                   |
| 合并                     | 不隐藏已有内容的从属单元格，不允许重叠合并                               |
| 不支持的依赖             | 命名区域、结构化/外部/三维引用、INDIRECT、共享/数组公式等会阻止结构转换  |
| 其他不能安全变换的元数据 | 冻结窗格或不透明引擎资源可能阻止结构转换，不能静默丢弃                   |

引用变换器不计算公式。公式结果由 Univer 产生；服务端保存公式输入，不伪造缓存值。旧客户端不能写入已升级的协议。

## 本地草稿与离线保存

宿主在浏览器 IndexedDB 中保存草稿，绑定当前用户和资源范围。插件通过受控桥接使用该能力，不能直接选择存储命名空间。

- 普通编辑保留本地草稿；只有明确点击“保存”才创建待提交意图。
- 断网时保留已排队的请求，恢复连接后重试。回执丢失时先确认原请求，再处理之后的新修改。
- 从“本地草稿”入口恢复或删除草稿。恢复需要在线重新授权；这是已加载会话的恢复能力，不是完全离线的应用。
- 不同标签页竞争通过比较修订处理，冲突另存一份草稿，不覆盖另一页内容。
- 每个宿主来源最多保存 20 份草稿，单份 20 MiB、合计 50 MiB。超限保留原数据并提示；清理浏览器数据或结束隐私会话可能删除本地副本。

Cloud 与其他 ChatKit 宿主的浏览器存储相互独立。需要跨宿主继续工作时，先完成服务端保存；无法保存时导出本地副本。

## 历史、恢复与选择性撤销

历史界面支持分页查看、只读预览、完整恢复以及撤销本人某个版本的单元格修改。

完整恢复产生新的提交，保留原历史，不把当前版本指针直接移回过去。选择性撤销只改变目标单元格，保留其他成员对独立单元格的修改；目标单元格之后已改变、发生 ABA 或已被撤销时拒绝。结构和旧快照版本使用完整恢复，不提供选择性单元格撤销。

## 选区与协作者

“引用选区”把输入、公式与计算结果分别交给 Assistant，并标明基准版本、本地编辑代次和未保存状态。编辑器等待当前计算完成；等待期间发生编辑、切换或远端增版会拒绝引用。选区上限为 200 格、32 KB，截断必须显式呈现。

远端单元格选区只在双方版本相同时显示；本地有未保存或结构草稿时暂不发送坐标，成员姓名仍可见。浏览器计算结果不能作为业务认证，也不会作为权威公式输入写回。

## 导入、导出与原生备份

导入先形成草稿，确认内容后显式保存。导入限制为 25 MiB、10 万单元格；这不是打开任意复杂 Excel 文件的承诺。

| 格式                   | 适用用途与限制                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| CSV                    | 交换表格值；不保存完整工作簿结构、格式或协作历史                                                     |
| XLSX                   | 支持值、公式、隐藏表、合并区域和数字格式；1900 日期系统保留数值与时间格式，1904 日期系统拒绝导入     |
| XLSX 复杂功能          | 图表、图片、宏、透视表、数据验证、命名区域、外链及复杂样式不能保证保留，应保留源文件                 |
| `.xpert-workbook.json` | 保存当前已提交模型及未知扩展，包含来源版本和校验摘要；恢复仅接受同一资源，先形成草稿，再保存为新版本 |

原生备份不包含完整数据库历史或权限，摘要也不是授权凭证。系统级备份与兼容回退见[部署与恢复](./operations)。
