---
title: '群聊中的工具结果展示'
description: '自动展示数据卡、资源卡与 MCP App 结果快照，并区分结果展示与最终答复。'
---

群聊中的 Assistant 可以自动发布工具产生的展示结果。工具需要输出平台已识别的展示类型；Assistant 无需再调用 `send_group_message` 复制结果。

## 当前支持范围

| 结果                 | 群聊中的展示               | 首期边界                                                             |
| -------------------- | -------------------------- | -------------------------------------------------------------------- |
| Widget 数据卡        | 复用现有 A2UI 数据卡组件   | 支持 flat A2UI messages；以只读快照展示，不转发源会话操作            |
| Resource Card 资源卡 | 标题、说明和已支持的内容块 | 快照本身不授予打开、下载或文件预览权限；这些操作暂不从复制的卡片发起 |
| MCP App              | 文本与结构化结果快照       | 不打开源 App iframe，不复制实例、令牌、工具输入或桥接通道            |

对于已经授权并接受的群聊资源，继续使用已有的共享资源入口或 `resource_open` 打开 Workbench；该路径仍会重新校验当前访问者的权限。

普通工具执行步骤、原始 `output` / `artifact`、推理、记忆和未知组件不会自动发到群聊。嵌套 JSON 恰好包含卡片字段，也不会被当作展示结果。未携带可展示结果的 MCP App、图片/音视频、legacy Widget config 和过大或格式错误的结果目前不会自动发布；可在有权限的处理记录中检查原始结果。

## 与回复完成状态的关系

展示快照是普通群消息（`intent: message`），不会唤醒其他 Assistant，也不会标记某个请求已经答复。

- `reply + progress`：部分结论，允许继续分析。
- `reply + final`：明确完成当前请求的答复。
- 已经通过工具发送 final 回复：结束阶段不再重复发送最终文本，展示快照仍会保留。
- 只有展示结果、没有文本：仍会保存和展示快照；快照本身不代替 final 回复。

同一个运行回复的展示内容会更新原来的群消息，消息顺序保持不变。刷新页面和重新连接后从同一份持久化记录恢复，不会重复追加卡片。运行生产者负责发布，群成员关闭页面不会阻止结果保存。

## 权限与数据范围

快照内容对群成员可见。对于通过共享资源分析接口产生的结果，平台会等待运行结束并重新执行分析交付检查，授权撤销或成员失效会阻止新的结果发布。已经成功发布的消息是群聊历史，不因源授权后来被撤销而自动删除。

展示看板定义、共享数据查询权限、打开资源和控制 App 会话是独立能力。快照不会扩大当前用户的数据权限，也不会共享源 Assistant 的会话凭据。

## 插件开发与验收

插件继续使用已有 `component`（`data.type: Widget` 或 `McpApp`）和 `resource_card` 消息，不需要新增 Provider 或修改工具名称。平台只按明确类型筛选并提取字段；流中的增量组件需要稳定 ID。一个运行回复最多投影 32 个块，单块最多 128 KiB，总快照最多 256 KiB；超过限制的块不发布。

验收时分别检查：有最终文本的卡片回复、只有卡片的回复、工具 final 回复后的卡片、刷新重连、共享分析授权撤销、普通工具和推理不外露。MCP App 在群中应展示结果快照，不能复用作者的交互会话。

后续若需要群成员操作 Widget、打开任意资源卡或使用交互式 MCP App，需要明确群聊动作路由、每位访问者的授权及统一发布规范；本期不增加该扩展接口。
