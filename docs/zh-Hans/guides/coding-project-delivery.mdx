内置 `@xpert-ai/plugin-coding-project` 插件使用 Project Tasks 和原生 Project Pipeline 编排软件交付。插件负责编码项目类型、Assistant 模板、技能和交付策略；宿主负责授权、任务执行、独立验收、Artifact 存储、人工决定和持久调度。

项目类型为 `applicationKey: @xpert-ai/plugin-coding-project:coding`、`projectTypeKey: coding`，没有注册旧类型别名或自动迁移。配置方法见[项目类型自定义配置](./project-application-types.mdx#项目类型自定义配置)，执行与评审语义见[项目任务](./project-tasks.mdx)。

## 选择本地验收或完整交付

项目配置的 `deliveryMode` 默认是 `local`：在现有云电脑内搭建或复用隔离开发实例，完成开发、安装、真实功能测试、独立执行验收和成果导出。此模式无需外部目标、远端仓库或发布审批；不能部署到宿主平台、推送 Git 或发布 npm。源码可以保存在本地 commit、源码归档或 Git bundle 中。

`release` 表示完整交付，才需要下述目标与仓库配置。用户要求发布时，使用 `mode: release` 和本地已验收的 `acceptedTaskId`，复用安装包及业务成果，不重新开发。已启动的流程固定其模式，之后更改项目默认值不改变历史或运行中流程。

Assistant 首先用 `coding_delivery_targets` 查询模式、`ready` 和具体 `blockers`；空目标列表在本地模式下是正常情况。预检只确认流程配置，不等同于 CLI 认证或依赖环境验收。任务开发及独立评审仍在云电脑中实际执行。

完整交付有多个已授权选项时，`CODING_DESTINATION_SELECTION_REQUIRED` 表示需要选择 `targetKey`、`repositoryKey` 后重新预检，并非缺少管理员配置。按用户需求选择，含糊时先澄清。重试沿用原目标与仓库，同时重新验证当前授权；目标策略改变时需要新一轮发布确认。

## 准备项目与交付目标

1. 加载插件，选择或创建编码项目。安装交付 Assistant 模板及所需技能，绑定项目并发布配置好的 Assistant。仅加载插件不会自动更新或发布已经安装的 Assistant。
2. 完整交付模式才需配置插件的 `targets` 和 `repositories`。每个目标都有明确的 `projectIds` 白名单；空列表不授权任何目标，新项目不继承其他项目的目标权限。
3. 选择可用且已授权的执行与独立验收 Runtime。插件本身不提供计算机，也不会让不支持执行验收的 Runtime 自动获得该能力。Pro 的 Computer Coding Runtime 可以使用云电脑内部的完整开发实例。
4. 通过所选环境的凭据助手或宿主已授权的 Connector 配置认证。凭据引用、仓库 URL 不等于执行通道已经就绪；需求、项目配置值和导出证据中不得保存密钥。

当前目标环境为 `development` 或 `acceptance`。URL 使用无凭据的 HTTP(S) 地址；替换和重启权限默认关闭。插件配置是目标白名单，不授予管理员权限。

| 目标模式                       | 准备方式                                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `deployment: cli`              | 配置目标登录或 CLI 凭据助手，使用 `coding_project.delivery@1.0.0` 流水线配置                                                                 |
| `deployment: current-instance` | 目标是宿主平台而非云电脑内部实例。使用含原生宿主安装节点的 `coding_project.delivery@1.1.0`；测试电脑需要不同可达地址时配置 `computerBaseUrl` |

使用 `delivery: github` 时，需要配置 `connectorBindingId`，使连接对该项目及仓库授权，并在发布前于 Assistant 的 Connector 节点显式选中连接。代码和 PR 写权限仍由 Connector 授权控制。

## 完整交付的阶段

| 阶段               | 责任与完成依据                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------- |
| 开发与独立验收     | Assistant 委派实现和测试，取得独立执行评审，再作正式任务决定；源码、安装包和报告导出为不可变 Artifact |
| 人工发布确认       | 人工审核精确候选、目标、安装包身份及替换/重启范围；Agent 没有审批工具                                 |
| 目标安装与独立验收 | 将已批准的包安装到授权目标，核对加载身份与真实行为，取得独立执行评审证据                              |
| Commit 或 PR 交付  | 向允许的分支交付已批准的源码 commit，或为该 commit 创建 PR；创建 PR 不会合并                          |

Assistant 可以从一次功能需求开始，将开发、部署、测试和普通恢复纳入所分配任务，不要求用户逐阶段提示。显式的人工发布确认仍是本流程的一部分。

已有验收成果需要发布时，向 `coding_delivery_start` 提供 `acceptedTaskId`。宿主固定原正式决定、版本及独立评审；材料整理任务补充缺失的发布元数据和导出物，同时保留原包字节，不为验证流水线而重新开发或打包。原验收被撤销或改变后，该固定引用失效。

原生[流水线视图](./project-pipelines/overview.mdx)展示节点、证据及决定。CLI 执行成功、评审任务完成、实施成果正式验收通过分别记录。

## 验证已批准的候选

当前实例交付由宿主安装节点自行读取人工决定及不可变安装包，在安装前核验身份和已授权的替换/重启范围。发布凭据留在宿主，交付插件不获得无限制的安装 API。

协调者通过 `coding_delivery_test_access` 查看回执，或为已加载候选申请有界的 MCP 测试访问。访问凭据写入限定 Project 与 publication 的文件，报告返回路径及到期时间，不返回密钥。该文件不能进入源码或 Artifact 导出。使用电脑可达地址时保留实际 MCP endpoint 路径。

MCP 访问是一种已支持的测试通道，不授予通用管理 API 权限，也不能证明其他插件能力可用。其他 API 或界面需要各自已授权的测试入口，以及与功能要求相符的证据。

固定 GitHub 交付使用 `sourceFormat: git-bundle` 的不可变源码，必须能够基于配置仓库的历史恢复已批准 commit。宿主侧固定 Git 程序导入临时 bare 仓库，不检出或执行候选代码；只创建批准分支，不 force-push、不合并，结果不确定时先查询远端再决定重试。

Git 写入分支为 `coding-delivery/<delivery-id>/v<requirement-revision>`；配置的基线分支是 PR 目标。GitHub 凭据留在固定程序中，不进入云电脑。真实远端交付仍需要可用连接及实际验证。

## 处理反馈与恢复

- 技术恢复在仍然有效时保留当前候选及轮次。安装、push 或 PR 响应不明确时先核实；没有响应不代表操作未发生。
- 业务变更创建新需求版本和 Round，重新提供候选证据及人工批准。源码、Artifact 或目标变化不能静默复用旧批准。
- 退回后，协调步骤读取已有反馈。通用人工节点目前没有文字评论字段；没有可读取的原因时，协调者应询问原因，而不是自行猜测。
- 独立评审者检查候选并记录发现，Assistant 决定接受、补验或返工；评审者不修补候选业务代码来制造通过结果。

持续运行的开发服务需要适当的环境所有者，有限 Coding 进程不能代替服务管理器。恢复保留授权、环境身份及其他任务成果；环境专属操作由技能说明，不搬入交付插件实现。

## 预算与完成边界

编码项目配置默认任务时长为 7,200 秒，受租户上限约束。修改只作用于新执行，不延长当前 attempt。任务时长与流水线 token 记账是不同限制。

原生流水线模型预算默认 2,000,000 tokens。登录的项目所有者或管理者可通过[插件参考](../../../packages/plugins/coding-project/README.md)中的审计管理 API 提高已有上限；追加保留历史消耗和批准，不会自动重启工作。流水线视图目前没有预算编辑入口。

`instance_native_llm` 账本覆盖经持久执行祖先链关联到原生流水线操作的宿主模型调用。CLI 代理用量及缺少该祖先关系的协调续跑尚未纳入，因此不是整个项目的 token 或费用总上限。

已安装、已加载、业务实测、正式验收和 Git 交付是不同结果。开发实例验收不能证明生产就绪、远端 Git 交付完成或任意项目均可自主完成。本文说明已实现流程，不代表某次运行的验收结论。
