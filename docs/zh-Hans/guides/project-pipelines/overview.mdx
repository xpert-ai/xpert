项目流水线在 Project 的协作和权限范围内，将业务流程、任务与真实执行记录连接起来。公共层提供持久化、协调、查询和泳道；插件提供领域对象、业务判断、展示文案与业务工作台。

公共功能已完成分批代码审核及本地候选验证。目标环境部署、业务插件配套验收和旧页面替换仍分别管理，参见[运行与验收边界](./operations)。

## 项目、配置和流水线实例

| 对象            | 作用                                                             |
| --------------- | ---------------------------------------------------------------- |
| Project         | 成员、Assistant、共享资源、任务和授权的协作容器                  |
| Definition      | 带版本的流程定义，描述角色、泳道、阶段和执行权归属               |
| Project Binding | 将模板绑定到项目中的执行器与允许修改的参数，保存修订号和定义摘要 |
| Instance        | 一个具体业务对象对应的流水线，同一项目可以包含多个实例           |
| Run             | 一次运行，固定定义和绑定快照                                     |
| Round           | 一轮输入版本，具有序号、generation、输入摘要及来源版本集合       |
| Node Instance   | 本轮的具体节点，关联任务、证据和执行归属                         |
| Task Execution  | 一次执行尝试，关联原生执行或 Runtime Invocation                  |

流水线工具栏的第一个选择框选择**当前项目中的流水线实例**，不切换项目。轮次选择框决定查看哪轮业务快照；模板选择在显式配置窗口内完成。

## 两种执行权归属

| 模式       | 流程事实与推进方                     | 公共平台职责                                                 |
| ---------- | ------------------------------------ | ------------------------------------------------------------ |
| `provider` | 插件维护业务拓扑、状态和推进规则     | 接收投影，原子保存 Task 与 Pipeline，呈现图和受控业务操作    |
| `platform` | 平台按照版本化定义协调每轮有向无环图 | 持久化派发意图，执行依赖与分支控制，处理回执、人工决定和恢复 |

一个定义只选择一种执行权。展示标签、图标、对象名称不能改变执行行为；配置不能嵌入任意可执行表达式。BOM 现有流程使用 Provider 接入，Code Review 使用平台协调定义，两者均通过扩展接口提供领域逻辑。

## 公共泳道与节点交互

从项目工作台或会话 Workbench 的**项目任务 → 流水线**进入。已有实例直接显示，只有配置按钮或显式配置意图打开配置窗口；保存配置不等于启动工作。

- 阶段泳道以角色为行、阶段为列，可选择泳道并过滤查看范围。执行时间轴用于观察执行先后和实际持续时间。
- 阶段标题和允许列表内的 `icon` 来自配置；工作节点复用阶段图标，控制节点使用其类型图标。
- 分支可读标签由投影提供，长标签换行。平台管理的 router outcome 标签仍有后续完善项，不承诺所有机器 key 都有自动翻译。
- 控制节点按相邻工作节点内联布局，不生成独立的“流程控制”泳道；布局不会修改业务归属。
- Assistant 信息集中在泳道上，工作节点卡片底部只展示本节点的执行圆点。
- 节点详情按概览、执行记录、证据版本组织内容。插件可以提供受阻原因、工作台入口和操作可用性。
- 历史轮次只提供追溯信息，不提供业务推进操作。导航往返与视图恢复保留对应实例、轮次及节点上下文。

Cloud 与 Desktop Workbench 复用公共远程组件。Desktop 的独立项目入口打开配置的平台页面，不代表独立项目页面已原生内嵌。

## 执行归属和状态

圆点必须同时匹配节点的显式 `executionIds` 与 `taskIds`，归属还绑定具体实例和轮次。没有归属的记录不会按 Assistant、任务名称或时间窗口猜测补入。节点和泳道汇总按原生执行 ID、Invocation ID、尝试 ID 的优先级去重；点击传递被显示的 `taskExecutionId`，不打开“最近一次执行”。

业务状态与执行状态独立。执行成功不代表业务审核通过；历史业务快照可以保持“受阻”或“拒绝”，同时对应执行圆点显示成功。读取时用有权访问的真实执行状态修正过时的运行展示，不回写历史业务快照。

## 统计维度与口径

| 维度           | 已提供的事实                                         | 解读要求                                                 |
| -------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| 流程与业务     | 当前轮次的工作、业务状态、待人工处理数量             | 当前业务状态不按历史执行窗口回溯重算                     |
| 实例与模板     | 按实例、模板版本、执行权归属分组                     | 项目内可跨实例汇总                                       |
| 执行器         | Assistant、Agent、Runtime Provider、工具或服务引用   | 只使用有归属的执行事实                                   |
| 执行结果       | 排队、运行、等待、成功、失败、取消、未知及终态成功率 | 成功率为成功数除以成功、失败、取消的总数；无终态为不可用 |
| 耗时           | 有效终态区间的总时长、均值、中位数和 P95             | 缺失起止时间不计作零耗时                                 |
| 重试           | 明确标记的技术重试，额外尝试及未分类尝试             | 多次尝试不自动等于技术重试或业务返工                     |
| 模型用量       | 已记录用量、按币种分组的成本与覆盖信息               | 不跨币种相加，不将未知费用当作免费                       |
| 排队与人工等待 | 持久化队列事实、观察到的人工就绪区间                 | 人工等待不是人的实际劳动时长，缺失事件需保留覆盖说明     |
| 跨项目         | 显式选中的、同一可信范围内有权读取的项目             | 不通过统计入口扩大授权                                   |

项目统计的执行窗口按实际开始时间筛选，采用 `[from, to)`，最长 93 天；业务状态取各实例当前轮次。全局汇总去重后不一定等于各实例行简单相加，界面同时保留共享执行和缺失时间等覆盖信息。

详细数据模型和扩展职责见[架构与插件接入](./architecture)。
