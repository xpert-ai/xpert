配置校验、保存绑定、启动执行、业务完成和实际交付是独立结果。配置保存成功不意味着已运行；目录可见不意味着有权执行；模型成功也不意味着业务已验收。

## 安全接入与恢复

1. 确认已登录用户、租户、组织和项目范围，再读取目录、绑定或流水线。
2. 校验模板版本、定义摘要、适配器引用和宿主能力；保存绑定仅使用表单允许的参数。
3. 启动或提交决定时，重新检查项目权限、真实执行目标、输入版本、节点和轮次状态。
4. 查询和轮询只读取事实。Provider 刷新更新投影，不调用业务推进操作。
5. 结果未知时检查原操作；确认副作用前不创建替代执行。取消请求与取消终态分开处理。

项目读取权限不自动赋予所有成员的会话或执行详情权限。Portfolio 对每个显式项目重新授权，不能用一个可读项目扩大访问范围。偏好与导航状态隔离到用户和项目；切换组织、账号或项目后不使用旧请求结果。

## 常见诊断

| 现象                     | 检查方向                                                                     |
| ------------------------ | ---------------------------------------------------------------------------- |
| 有任务但节点没有圆点     | 检查持久化的节点、轮次、Task Execution 归属；不要根据 Task 或 Assistant 猜测 |
| 执行成功而节点仍受阻     | 分别查看执行终态、业务判定和历史快照，确认是否仍需业务验收                   |
| 配置列表为空或绑定不可用 | 检查插件实际加载、贡献来源、宿主协议、项目权限和角色候选范围                 |
| 工作台入口不可用         | 检查该节点的 Provider 展示与授权；历史节点不提供业务推进入口                 |
| 长时间等待或 unknown     | 检查持久化意图、租约、原执行回执及 inspect 结果，避免盲目重发                |
| 统计与实例行相加不同     | 检查执行去重、共享执行、当前业务范围及实际开始时间窗口                       |
| 403 或目标空间不可见     | 先核对组织上下文，再确认实际授权；不通过数据库改写权限绕过                   |

## 兼容性

Contracts 与 SDK 必须配套构建和验证；能力判断使用显式宿主协议和能力声明，不凭包版本号或名称推测。核心包采用统一版本管理也不自动证明接口兼容。

`ProjectTaskExecutionTarget` 是联合类型。需要继承 Assistant 目标时使用具体的 `ProjectTaskAssistantExecutionTarget`；运行时使用 `kind` 区分目标，不根据是否出现 invocationId 判断类型。外部包消费需验证严格声明、CJS、ESM 与 Bundler 入口。
