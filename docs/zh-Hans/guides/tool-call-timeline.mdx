title: 工具调用时间轴
description: 活动组、描述性调用摘要、有界预览和按需读取的完整详情。
---

工具调用时间轴按“活动组 → 单次调用 → 完整详情”展示执行过程。连续工具调用保持原有顺序；助手正文、独立成果和不同执行范围构成分组边界。

## 活动组表达什么

组头分别展示活动图标、活动标题、调用次数和执行状态。活动来自工具声明的 `kind` 与 `action`，不根据工具名、标题或输出中的关键字推断，也不额外调用模型生成摘要。

| 组内活动             | 标题示例             | 图标       |
| -------------------- | -------------------- | ---------- |
| 全部为技能读取       | 读取技能             | 技能扳手   |
| 全部为文件读取       | 读取文件             | 文件       |
| 文件读取、写入和查找 | 文件操作             | 文件       |
| 全部为数据查询       | 查询数据             | 数据库     |
| 浏览器与命令两种类型 | 浏览器操作与命令执行 | 通用活动组 |
| 三种及以上类型       | 工具活动             | 通用活动组 |
| 文件与未声明活动混合 | 文件操作与其他工具   | 通用活动组 |
| 全部未声明或无效     | 工具调用             | 通用工具   |

类型顺序取组内首次出现的位置，不随完成顺序或语言改变。同一执行范围内的调用更新合并为一行；独立重试按新的调用身份计数。“2 次调用”不等于两个文件：同一技能读取两次仍是两次调用。

状态独立显示进行中、已完成、部分失败、失败、等待输入、已取消或状态未知。没有结束状态的调用不会被推断为成功。取消需要明确的取消状态；暂停通过运行状态呈现。失败组显露失败项和简短错误。用户手动展开或收起优先于后续自动折叠。

## 调用标题与操作对象

声明为 `command` 的活动组与调用行共用终端图标，不再由历史事件中的旧 SVG 覆盖调用行。静态形态与运行中的 `code-thinking` 逐帧动画配对，继承当前主题颜色。动画采用 100 帧图集与约 1.67 秒的循环节奏。

组收起时由组图标提示执行中；展开后由实际运行的调用行播放动画。完成、失败、取消、暂停及缺少有效运行状态的历史调用保持静态。页面隐藏或开启减少动态效果时停止动画，资源加载失败时保留静态图标。状态文字始终保留，不依赖动画表达执行结果。其他活动类型的自定义图标继续按原有规则展示。

调用行显示描述性标题、简洁操作对象、状态和耗时，例如：

```text
读取技能文件  live-dashboard/SKILL.md              已完成 · 26ms
```

Skill 与 Sandbox Files 工具提供“读取技能文件”“列出目录”“创建文件”等标题。Shell 展示命令摘要；Live Dashboard 提供数据验证、登记和看板保存等操作标题。未提供可用描述性标题时显示“工具调用”。技术工具名只在完整详情的“调用信息”中展示。

参数校验可能在工具发出开始事件前失败。失败事件仍保留注册工具的多语言标题、图标和活动声明；该工具的公开错误投影优先于父节点继承的元数据。未知工具使用通用标题，不借用父节点标题。

操作对象来自工具对**已允许公开的输入**的格式化。行内不拼接原始参数 JSON；完整参数仍可在调用详情中查看。工具的实时进度不替换其稳定操作标题。

“使用的技能”继续作为回复级信息按技能身份去重。技能读取使用普通工具生命周期，不另外生成 `Computer` 卡片，也不从调用次数推算技能数量。

## 预览与完整内容

展开调用后，输入、输出和实际错误分别展示。预览遵循统一预算：

每个分区的标题、类型与大小统计、复制按钮和 JSON 视图切换共用紧凑工具栏，不重复展示 JSON 类型说明。窄屏允许工具栏自然换行；长文本和展开的 JSON 树在有界区域内滚动，不继续撑高时间轴。

| 内容                 | 时间轴预算                                     |
| -------------------- | ---------------------------------------------- |
| 文本、Markdown、日志 | 最多 6 行，同时不超过 2 KiB UTF-8              |
| JSON 对象、数组      | 每个集合最多 5 项、最多 2 层，同时不超过 2 KiB |
| 技能说明、文件正文   | 工具可声明只显示读取结果与实际大小、行数       |
| 流式输出             | 更新有界预览；结束后提供可用的完整快照         |

完整、合法的 JSON 对象或数组字符串也按结构化内容预览。普通文本、未完成的 JSON 和标量字符串仍按文本处理。统计取自允许公开的完整结果；空文本、`null`、`false`、`0`、空集合与缺失输出分别处理。文本末尾的换行符不额外计为一行。

截断内容明确标记为“仅展示部分内容”；仅摘要模式说明正文已收起。“复制预览”只复制可见预览，“复制完整内容”读取并复制完整的可查看快照。运行未完成、未公开、未记录、快照不可用和加载失败均有对应提示；加载失败可以重试。

“查看完整内容”打开统一、可调整尺寸的弹层，支持输入、输出、错误切换。长文本分段加载，JSON 在完整内容能放入一段时提供树形和原始视图。关闭或切换内容会取消当前读取；键盘关闭后焦点返回原入口。弹层使用当前主题和圆角，调用区域响应密度设置，适配窄屏。

历史快照即使标记为文本，完整内容可解析为 JSON 对象或数组时也提供树形视图。已截断的历史预览仍按文本显示，不猜测或补齐缺失字段；完整快照仅在用户打开详情后读取。

弹层不替换 Workbench 的看板视图。原有图片、Widget、附件、成果入口及 `category: 'Computer'` 的渲染用途保留。

## 图片查看

图片工具可声明 `activity: { kind: 'image', action: 'view' }`，并在所属工具的 `publicToolPresentation` 中显式设置 `attachments: 'images'`。平台仅从成功调用的标准 `xpert.tool-output` artifact 投影经过校验的图片引用到 `presentation.images`；仍需分别声明允许公开的输入、输出和错误。

展开活动组后显示缩略图，点击打开大图；参数和文本结果收在“参数与结果”内。组头分别统计调用次数和不同固定版本的图片数量，同一图片重复查看不会重复计算图片数量。混合活动继续遵循统一分组规则。

图片引用包含 Artifact、固定版本和校验和，预览通过宿主授权取得短期链接，历史中不存图片字节或签名 URL。每个 artifact 最多接受 20 个经过校验的 PNG、JPEG 或 WebP 图片引用。未声明展示的旧 artifact 和内嵌 Base64 不会自动成为图片预览；失败或取消会清除之前的图片预览，后续通用结束事件不能将其恢复。访问失败时显示重试入口。图片弹层使用当前主题、圆角和密度。

已有 `view_image` 插件提供上述声明。需要配套更新插件、共享协议、服务端与 ChatKit UI；旧历史不会自动补写新声明。

## 工具接入

工具定义通过已有 `metadata` 提供描述性标题、图标和 `ToolDisplayDeclaration`。声明中的 `tool` 必须匹配所属工具，防止嵌套调用继承其他工具的展示回调。公开展示策略的缓存按执行范围、调用 ID 和工具名隔离；另一次执行复用调用 ID 时，不会继承之前的图片展示授权。

```ts
import type { ToolDisplayDeclaration } from '@xpert-ai/contracts'

const toolDisplay: ToolDisplayDeclaration = {
  tool: 'read_project_note',
  activity: { kind: 'file', action: 'read' },
  target(publicInput) {
    if (!publicInput || typeof publicInput !== 'object' || Array.isArray(publicInput)) return
    return typeof publicInput.path === 'string' ? publicInput.path : undefined
  },
  outputMode: 'summary',
  outputSummary: { en_US: 'Note read', zh_Hans: '已读取说明' }
}

const metadata = {
  toolName: { en_US: 'Read project note', zh_Hans: '读取项目说明' },
  toolDisplay
}
```

此声明只影响展示，不授予数据访问权限。`target` 最长 160 个字符；结果摘要使用已有多语言文本类型。成功结果才使用声明的结果摘要，错误独立呈现。

| kind      | 允许的 action                                               |
| --------- | ----------------------------------------------------------- |
| `skill`   | `read`                                                      |
| `image`   | `view`                                                      |
| `file`    | `read`、`write`、`list`、`search`、`delete`、`move`、`copy` |
| `data`    | `discover`、`query`、`validate`、`register`                 |
| `browser` | `navigate`、`read`、`interact`、`capture`                   |
| `command` | `execute`                                                   |
| `search`  | `search`                                                    |
| `content` | `create`、`update`、`save`、`read`、`list`                  |
| `task`    | `create`、`update`、`read`                                  |

多操作工具可通过 `activity(input)` 根据已校验、允许展示的操作参数返回上述组合。解析由工具拥有；声明在本次调用首次投影时确定，后续更新复用。无效声明回退为未知活动，不中断工具执行。新增活动组合需要先扩展共享协议及其校验、翻译和图标映射。

## 数据与权限边界

服务端先执行 `PublicToolPresentation` 可见规则，再生成摘要、裁剪预览、保存详情快照并发出事件。模型接收的原始工具结果不受展示裁剪影响。新事件和历史展示字段只携带有界预览及可选 `presentation`，不为展示目的重复传输无界正文。

完整详情是调用当时允许参与者查看的数据快照，不是稍后重新读取工作区文件。引用绑定会话、执行、调用和输入/输出/错误阶段；内容不可用时不会回退到私有 artifact 或当前文件内容。

ChatKit 通过 `@xpert-ai/xpert-sdk` 的 `client.conversations.getToolDetail(reference, { offset, signal })` 读取快照。接口位于既有 AI 会话边界：

```text
GET /api/ai/conversations/:conversationId/tool-details/:id
    ?executionId=...&toolCallId=...&phase=output&sha256=...&offset=0
```

每次读取重新验证会话访问、适用的 Assistant/会话凭证范围以及持久化的执行归属。返回内容前再次检查访问权限。引用和哈希不是授权凭证；响应使用 `Cache-Control: private, no-store`。

## 历史兼容与部署限制

- `presentation` 是可选扩展。缺少声明的历史调用按通用工具显示；已有声明按执行时保存的语义回放，不使用当前工具定义重分类。
- 历史消息只有预览时，不伪造完整内容入口；已保存完整旧内容可以在客户端限制预览并本地查看。历史正文不会通过此次升级自动补存快照。
- 每份序列化详情快照上限为 50 MiB；超过上限或保存失败时，保留摘要与预览并提示完整内容不可用。此上限不替代工具自身的输出限制。
- 详情每次返回最多 16,384 个 UTF-16 单元，不切断代理对；使用返回的 `nextOffset` 翻页。完整复制需要读取所有分段并占用客户端内存。
- 快照存放在已有项目或用户卷的 artifact 字节存储中。底层卷删除、权限撤销或执行记录缺失会导致内容不可用。
- 部署需配套更新共享协议、SDK、Xpert 服务端和 ChatKit UI。UI 构建检查要求 SDK 提供 `getToolDetail`；本地源码联调不代表这些包已经发布。
- 平台通用实现位于 Xpert、ChatKit 和 SDK；Live Dashboard 插件提供自身的工具声明。无需另写 Pro 专属时间轴逻辑。
