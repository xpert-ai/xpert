协作空间是 Assistant 的一种插件能力。启用后，用户可以在 ChatKit Workbench 中打开空间，浏览项目文件、创建页面、收集工作成果，并与项目成员共同编辑文档。多个 Assistant 可以连接同一个项目，使用同一份内容。

本系列文档描述当前源码能力，取代此前的 Spaces 实施计划。使用时需要配套的平台、SDK、ChatKit 和插件版本；当前源码联调与正式发布的区别见[架构与扩展](/zh-Hans/architecture/spaces-content#发布与部署)。

## 空间、项目与 Assistant

空间在技术上是内置的 `platform/space` 项目类型。项目管理成员、角色、Assistant 连接、文件工作区和归档状态；Spaces 插件提供空间视图及额外的内容元数据。

- 一个项目对应一个空间元数据记录，多个 Assistant 不会创建多份空间内容。
- 页面正文以 Markdown 文件保存，上传的文件和收集的成果也保存到项目文件工作区。
- 空间数据库记录保存标题、目录关系、资源标识、导入来源等元数据，不另建一套空间文件盘。
- Assistant 配置了空间能力，并不自动赋予用户所有项目的访问权限。

## 开始使用

1. 为 Assistant 配置并发布协作空间能力，安装匹配的空间视图与 Markdown 编辑器插件。
2. 创建或选择协作空间类型的项目，将需要共同工作的 Assistant 连接到该项目。
3. 为团队成员分配项目角色。
4. 在 Assistant 的 ChatKit Workbench 中打开“协作空间”，创建页面、上传文件或导入文档。
5. 点击页面，在同一个 Workbench 内打开 Markdown 编辑器。切换 Assistant 后，只要仍访问同一项目和资源，就会进入同一份文档。

没有项目上下文时，需要先选择项目。空间不会根据 Assistant 名称或创建人隐式选择一个私人目录。

## 浏览与整理内容

| 功能       | 行为                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 全部内容   | 汇总空间页面、项目文件及收集的成果，显示名称、类型、来源和更新时间       |
| 页面       | 浏览已注册的 Markdown 页面，点击后交给平台解析对应编辑器                 |
| 文件与成果 | 浏览上传的项目文件和已收集的 artifacts；具体编辑能力取决于已安装的编辑器 |
| 文件夹     | 按项目文件目录浏览、创建、重命名和移动内容                               |
| 搜索       | 按当前列表范围查找内容；正文检索使用绑定的知识库                         |
| 最近更新   | 按内容更新时间查看，含义不同于个人最近访问                               |
| 回收站     | 查看已移入回收站的内容，并在权限允许时恢复                               |

标题、搜索、新建和访问范围组成紧凑的操作区域。“访问范围”展示项目共享边界，不是另一套独立的空间邀请系统。

文件移动和重命名保留资源标识，已有文档引用仍可解析。遇到目标路径冲突时，操作会被拒绝，不会覆盖另一份文件。目录移动涉及实际文件路径；页面的父子关系另见[子页面](/zh-Hans/guides/spaces-markdown#子页面)。

## 创建与收集

- **新建页面**：从空白或内置模板开始，生成项目中的 Markdown 文件。
- **上传文件**：保存到当前项目目录，后续可引用、下载，或由匹配的编辑器打开。
- **收集成果**：将有权读取的 artifact 版本收集为项目内容。原始成果的访问权限不会因此被修改；复制到项目后，副本按项目权限共享。
- **从文档平台导入**：读取已授权来源并创建本地副本，参见[文档来源导入](/zh-Hans/guides/spaces-document-sources)。

不支持编辑的文件类型仍可作为文件管理或下载。空间列表不会把所有文件都当作 Markdown 打开。

## 多人与多 Assistant 协作

空间使用项目的协作基础，不维护独立成员名单。

| 项目角色或状态 | 空间权限                             |
| -------------- | ------------------------------------ |
| 所有者、管理员 | 阅读、编辑，并执行项目及空间管理操作 |
| 编辑者         | 阅读和编辑内容                       |
| 普通成员       | 阅读内容                             |
| 已归档项目     | 只读，写入操作被阻止                 |

服务端还会验证租户、组织、项目成员身份、Assistant 与项目的连接，以及入口所需的插件能力。界面隐藏操作不是唯一的权限控制。文件下载、引用解析、协作消息和知识检索都会检查对应资源权限。

同一 Markdown 文档的实时协作、保存状态和冲突处理见[Markdown 协同编辑](/zh-Hans/guides/spaces-markdown)。AI 生成、修改提案、评论与通用审阅由 Assistant 和 ChatKit 提供，空间视图只负责内容入口与整理。

## 文档检索

项目管理员可以启用项目内置知识库。知识库按项目绑定，Spaces 中的知识库标识只是该绑定的缓存，不形成独立的权限边界。

1. 正文先保存到项目文件，再发布内容投影和索引任务。
2. 默认使用关键词检索，无需先配置 embedding 模型。
3. 索引显示待处理、处理中、就绪或失败状态，失败后可以重试。
4. 检索结果再次检查当前资源权限和文件版本；已失效或与索引不一致的内容不会作为有效片段返回。

索引失败不会撤销已经保存的文件。修改刚保存但尚未完成索引时，正文检索结果可能暂时不包含新内容。

## 界面与语言

Remote View 使用共享的 shadcn/ui 组件与 Tailwind CSS。字体、密度、颜色和圆角由宿主传入的主题变量驱动，避免各插件重复覆盖组件样式。

视图文案集中维护英文与简体中文词条，包括按钮、空状态、错误提示和无障碍标签。业务组件引用翻译键，不在 JSX 中嵌入双语判断。内容标题和正文是用户数据，不自动翻译。

## 能力边界

当前提供项目文件、Markdown 协作、资源引用、知识检索与文档来源导入。以下能力不能从当前功能推导为已经交付：

- 任意格式的 Word、表格或幻灯片实时协作；它们需要各自的编辑器与格式协议。
- 飞书等外部平台的双向同步、原文回写或自动定时更新。
- 持久化的离线编辑队列、跨项目引用或包含全部附件的离线导出包。
- 在 Spaces 内另建通用 AI 对话、审阅或自动维护引擎。

开发者可继续阅读[平台架构与扩展](/zh-Hans/architecture/spaces-content)。
