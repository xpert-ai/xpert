在 **模型提供商**（`/copilot/basic`）中统一管理连接凭据、启用模型和默认模型。Assistant 选择模型时会保留具体连接，避免同一提供商下的同名模型混淆。个人可调用的模型可在 **设置 → 个人 → 可用模型**（`/settings/account/models`）查看。

## 提供商、连接、模型类型与默认用途

| 概念     | 含义                                                     | 示例                               |
| -------- | -------------------------------------------------------- | ---------------------------------- |
| 提供商   | 提供模型协议、凭据表单和模型目录的集成                   | 通义千问、OpenAI-API-compatible    |
| 连接     | 一套独立的命名配置，包含凭据及提供商支持的服务地址等字段 | 同一提供商的“生产连接”和“测试连接” |
| 模型类型 | 模型的真实能力类别                                       | LLM、文本嵌入、实时语音            |
| 默认用途 | 某个业务场景没有指定模型时使用的默认绑定                 | 主模型、备用模型、推理模型         |

模型绑定由 **连接 ID + 模型类型 + 模型 ID** 确定。显示名称相同不表示同一个绑定；切换到另一个连接下的同名模型，也属于模型切换。

连接不再通过“主模型提供商”或“嵌入模型提供商”限定用途。同一个连接可以提供多种类型的模型，也可以被多个默认用途引用。模型是否出现在选择器中，取决于真实类型、连接与模型状态，以及当前用户的访问权限。

## 配置提供商连接

### 新增与编辑

1. 打开模型提供商页面，确认当前显示的是组织配置还是系统配置。这里的系统配置指当前租户级配置。
2. 在目标提供商上选择 **添加 API 密钥**；已配置的提供商可以通过 **配置 → 添加连接** 新建另一套连接。
3. 为连接设置易于识别的名称，并填写提供商要求的凭据、服务地址或其他字段。
4. 保存配置。使用共享凭据的提供商会验证凭据，并自动启用当前可用、未弃用的预置模型。

不同提供商的凭据要求不同。需要逐模型配置凭据的提供商可以先创建空连接，再通过 **添加模型** 配置和验证具体模型。新增自定义模型或通过发现功能导入的模型，需要在 **管理启用模型** 中确认启用。

编辑已有连接会保留原来的模型启用范围。历史连接也不会因为升级而自动扩大范围；明确保存过的空启用列表仍表示没有启用任何模型。

### 在多个连接之间切换

提供商右侧的 **配置** 入口显示当前连接及状态。打开后可查看连接数量、各连接的名称、状态和启用模型数，并进行选择、编辑、启用或停用操作。

选择另一条连接只改变当前管理视图：下方模型列表随之切换，默认模型和 Assistant 已保存的绑定不会自动改变。

| 状态         | 含义与处理方式                                   |
| ------------ | ------------------------------------------------ |
| 已启用       | 连接已开启；实际调用仍取决于凭据、模型及访问权限 |
| 已停用       | 连接不可用于正常模型调用，需要重新启用           |
| 验证失败     | 检查凭据及提供商配置后重新保存                   |
| 目录加载失败 | 模型目录未能读取，检查连接或稍后重试             |
| 待启用模型   | 当前启用集合为空，通过管理启用模型选择可用项     |

停用连接前，界面展示默认模型、已保存模型绑定和 Assistant 草稿的引用数量。仍被显式默认模型引用的连接不能直接停用，需先调整默认设置。停用也可能使其他已有绑定不可用。本页面不提供连接的永久删除入口。

## 管理连接中的模型

页面支持按提供商、连接或模型搜索，并按全部、已配置、待配置、异常状态筛选。

提供商信息下方、模型列表上方是操作栏：

- **显示模型 / 收起**：控制列表展开，并显示启用数与模型总数。
- **管理启用模型**：按名称和类型筛选，勾选单项，或选择、清空当前筛选结果。
- **发现模型**：仅在提供商支持时显示，用于获取可导入的模型。
- **添加模型**：仅在提供商支持自定义模型时显示。

模型表格展示类型、名称、支持能力、上下文长度、启用状态和 **属性与参数**。缺少有效上下文长度时显示横线。属性详情与个人可用模型页面共用展示方式，管理者可以检查未启用模型的属性；管理目录不等同于当前用户可调用的目录。

要让某个连接仅用于嵌入模型，在 **管理启用模型** 中只保留文本嵌入类型。旧连接曾经设置的 `embedding` 角色不会自动将它的全部目录变成嵌入模型。

## 在 Assistant 中选择模型

创建或编辑 Assistant 时，模型选择器按连接区分来源。同一提供商的多个连接可以分别出现；每条连接下只列出符合当前场景类型要求且用户有权使用的模型。

例如，“生产连接”和“测试连接”都提供同名 LLM 时，可以分别选择并保存。保存后绑定的是所选连接，不会随模型提供商页面当前查看的连接而变化。LLM 选择器不会把文本嵌入模型当作 LLM；但同一连接下独立启用的 LLM 仍可正常选择。

选择器支持搜索、能力筛选和调整提供商列宽。模型标签显示连接信息，参数入口打开 Dialog。模型不可用时应修复该绑定或主动选择替代模型，不会因名称相同自动改用其他连接。

## 默认模型设置

选择页面顶部的 **默认模型设置**。所有用途放在同一个连续列表中，不再区分“角色默认模型”和“其他模型类型”。

| 默认用途       | 对应模型类型   |
| -------------- | -------------- |
| 主模型         | LLM            |
| 备用模型       | LLM            |
| 推理模型       | LLM            |
| 嵌入模型       | 文本嵌入       |
| 实时语音模型   | 实时语音       |
| 文本转语音模型 | TTS            |
| 语音转文本模型 | Speech-to-text |
| 图像生成模型   | Image          |
| 视频生成模型   | Video          |
| 重排序模型     | Rerank         |
| 内容审核模型   | Moderation     |

主模型、备用模型和推理模型是三个独立用途，即使都要求 LLM，也可以绑定不同连接或不同模型。推理用途目前按 LLM 类型校验，不通过模型名称猜测推理能力。备用用途由具体业务调用选择，设置该项本身不代表开启通用自动故障切换。

### 配置方式与生效范围

| 配置方式     | 行为                                             |
| ------------ | ------------------------------------------------ |
| 指定模型     | 为该用途保存明确的连接、模型及参数               |
| 继承系统默认 | 组织使用当前租户的对应默认模型；只在组织范围提供 |
| 未配置       | 明确不为该用途提供默认模型，不再沿用历史配置     |
| 沿用历史默认 | 兼容尚未迁移的旧配置；改为新配置后以新设置为准   |

尚无新设置时，系统优先保留组织内可读取的历史默认，再按规则解析租户默认。明确选择继承后，使用租户默认，不再使用组织历史值。显式配置的模型失效时显示不可用，不会静默替换成其他模型。

指定模型时可以编辑参数；继承的模型与参数在组织中只读。如需不同参数，应改为指定模型。参数编辑完成后返回默认列表，最后保存整个 Dialog。

修改默认设置不会批量修改 Assistant 的固定模型绑定。嵌入默认用于新建知识库等需要解析默认嵌入模型的场景；已有知识库索引继续使用原模型，不会自动重建。

## 切换模型时处理参数

当连接或模型发生变化时，系统读取目标模型的参数规则并展示变更确认：

- **重置参数**：使用目标模型的默认值，移除旧模型独有或没有目标默认值的可选参数。
- **保留兼容参数**：仅保留满足目标字段类型、范围和选项约束的值，其余按目标规则处理。

缺少必填参数时需要补齐后才能确认。参数规则加载失败不能提交；取消切换会保留原绑定。快速连续切换时，旧请求的结果不会覆盖当前选择。

同一模型已保存的合法覆盖值继续生效，包括 `0` 和 `false`。可选参数可以清空；在保留兼容参数的策略下，显式清空仍表示未设置，不会被自动填回默认值。

## 批量替换 Assistant 模型

此功能用于更换模型版本或连接，当前范围为 **LLM 草稿绑定**。

1. 选择 **批量替换助手模型**，必要时限定工作空间。
2. 选择源模型和目标模型。源列表从有写权限的现有草稿提取，因此已下架的模型仍可作为替换来源。
3. 选择重置参数或保留兼容参数，然后预览影响。
4. 查看各 Assistant 的引用数量和参数差异，勾选要更新的条目并执行。缺少必填参数的条目不能直接执行。
5. 查看成功、失败、冲突或跳过结果；成功条目可在结果中执行恢复。

替换精确匹配连接 ID、模型类型和模型 ID，不会影响其他连接的同名模型。范围包括 Assistant 草稿默认模型、所属 Agent 和分类器节点；不修改只读引用的其他 Assistant、已发布版本、知识库向量索引或 fallback 配置。要让已发布 Assistant 使用更新后的草稿，仍需正常发布。

每次执行最多选择 **100 个 Assistant**。当前工作空间范围内检索到超过 **500 个 Assistant** 时，需要缩小范围。执行时重新检查写权限、目标可用性和草稿版本；其他人已修改的草稿不会被覆盖。每个草稿独立提交，部分失败不会撤销其他成功条目。

恢复只允许操作发起者在仍有写权限、且草稿未发生后续修改时执行，避免覆盖新的编辑。目标模型缺少当前目录中源模型声明的能力时，会阻止替换。

## 会员授权与个人可用模型

会员模型配置使用连接、真实模型类型和模型 ID 区分授权项。同名模型可以来自不同连接；嵌入模型显示其真实类型，不再统一标为 LLM。

新授权规则使用完整模型身份，历史未记录类型的规则保留原有匹配语义。模型目录展示的变化不会自动扩大历史会员权限。失效或无法识别的历史配置保留为待修复项，不能因为显示名称相同自动映射到另一条连接。

个人 **可用模型** 页面展示当前用户实际有权使用的模型。启用一个模型并不等于向所有成员授予访问权限，调用仍受现有作用域与授权规则约束。

## 安装和更新提供商插件

滚动到页面底部的 **安装模型提供商** 区域时，自动加载可安装、未弃用的模型插件。宽屏采用五列卡片，窄屏自动调整；卡片显示图标、名称、作者和简介，目录有下载量时才展示该信息。

悬停卡片会显示紧凑的 **安装** 和 **详情** 按钮，操作层不增加卡片高度；键盘聚焦及触屏同样可以访问操作。搜索、加载失败重试和空状态均在该区域处理。**Xpert Marketplace** 入口可打开完整插件市场。

提供商标题旁显示插件运行版本；存在可用更新且当前用户有权限时，提供 **更新** 入口。安装、详情、更新及必要的重启提示复用现有插件管理流程。安装插件后，仍需完成相应连接或模型凭据配置。

## 升级与兼容

升级通过正常的 API 构建与数据库 `schema-sync` 流程，在实体结构同步后自动执行旧默认模型迁移：

| 旧提供商角色 | 新默认用途 | 所需模型类型     |
| ------------ | ---------- | ---------------- |
| `primary`    | 主模型     | `llm`            |
| `secondary`  | 备用模型   | `llm`            |
| `reasoning`  | 推理模型   | `llm`            |
| `embedding`  | 嵌入模型   | `text-embedding` |

迁移按租户和组织分别处理，将有效旧配置保存为指定模型，保留连接 ID、模型类型、模型 ID 和参数。已有的指定、继承或未配置记录不会被覆盖；重复执行不会重复创建。连接、凭据、旧字段及原模型记录保留，不通过删除重建完成迁移。

同一作用域内存在多个相同旧角色时，按创建时间、ID 确定第一个启用连接。空模型、错误类型或不符合参数结构的记录不会强制迁移；如果首选记录无效，也不会静默选择后面的连接。原记录保留，管理员可在默认设置中修复。新增的语音、图像、视频等用途没有旧角色可迁移，需指定或继承已有租户默认。

未迁移的有效旧默认继续通过兼容读取生效。迁移后以新默认配置为准，不进行新旧字段双向同步，也不回写旧版本配置。

对接代码应使用 `DefaultModelRole` 表示默认用途，使用 `AiModelTypeEnum` 表示模型类型。`AiProviderRole` 已废弃，仅保留历史兼容；旧按角色读取入口也保留。同步到其他发行版时，应同时携带契约、实体、迁移 SQL、统一解析逻辑和界面，不能只复制页面。

## 常见问题

**新连接是否必须手动启用全部模型？** 共享凭据连接验证成功后会自动启用当前可用预置模型；模型级凭据、自定义和新导入模型，以及历史显式空列表，需要相应配置。

**为什么切换提供商页面中的连接后，Assistant 仍使用原连接？** 页面切换只改变管理视图。请在 Assistant 的模型选择器中修改绑定，或使用批量替换更新草稿。

**为什么迁移后默认模型仍不可用？** 迁移保留配置，但不会修复失效凭据、恢复下架模型或扩大授权。检查连接、启用列表、真实类型和权限，再重新指定可用模型。

**是否包含平台消息额度与 API Key 的优先级路由？** 当前功能使用独立连接和既有授权规则，不包含平台额度与自有密钥之间的自动优先级切换。
