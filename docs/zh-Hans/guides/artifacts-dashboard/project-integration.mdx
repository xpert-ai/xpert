Live Dashboard 在 Assistant ChatKit 的 Workbench 中提供看板 View。Project 为对话、制作文件和看板资源提供共同范围；ChatKit 和看板 View 使用同一份宿主项目状态。

## 开始使用

1. 从“实时看板助理”模板配置 Assistant，选择或新建一个实时看板项目。
2. 在 ChatKit 中提出需求，沿用来源发现、真实预览、创建和保存草稿的制作流程。
3. 点击资源卡片，或在 Workbench 打开实时看板。通过 `项目 / 看板` 入口选择需要查看或编辑的看板。
4. 继续在同一 Artifact 上修改。管理员确认具体草稿修订后发布正式版本，再按需开启团队分享。

看板制作不要求先建 Project Task 或经过制作验收流程。平台的任务和 Pipeline 能力独立使用；Project 页面不额外承载 Live Dashboard View。

## 项目类型与 Assistant

插件贡献实时看板项目类型：`applicationKey: @xpert-ai/plugin-live-dashboard:live-dashboard`、`projectTypeKey: dashboard`，绑定平台 Project。它用于创建入口、项目分类和 Assistant 默认工作范围，不建立另一套项目数据或权限系统。

`live-dashboard-assistant` 模板采用 `workspaceScope.mode: project-required` 并指定该类型；未选择项目时，ChatKit 使用既有的项目选择和创建引导。已有 Assistant 的模板升级沿用平台流程，不因安装插件而自动改写其配置或发布状态。

可选的 `live-dashboard-monitor` 模板在项目内检查明确选定的正式看板，只报告数据绑定可用性、结果完整性以及有证据的业务新鲜度。它不修改或发布看板，只在用户要求时安排任务；查询时间不等于业务数据更新时间。

## 双栏级联选择器

一个入口显示 `项目 / 看板` 路径，展开后同时显示两个列表：

| 左栏：项目                                        | 右栏：看板                            |
| ------------------------------------------------- | ------------------------------------- |
| 当前用户可读、未归档且当前 Assistant 可使用的项目 | 当前项目内有权读取的看板              |
| 独立搜索、滚动列表与分页                          | 独立搜索、滚动列表与分页              |
| 高亮当前项目，选择后请求宿主切换                  | 高亮当前看板，选择后打开准确 Artifact |
| 新建项目使用 ChatKit 的既有入口                   | 标题区提供“新建看板”                  |

两个列表每页最多 20 项，页码居中，边界处禁用上一页或下一页。搜索只重置自身页码；看板搜索覆盖项目内全部可见看板的标题和 Artifact ID，而非仅搜索已加载的一页。编辑者按草稿标题搜索，成员按正式标题搜索，不暴露无权读取的草稿标题。

键盘焦点默认定位到列表中的当前项，支持方向键及回车选择。窄面板中路径入口可单独占一行；弹层仍保持左右两栏，长名称截断并可查看完整标题。

## 与 ChatKit 双向同步

View 选择项目时，通过已声明的 `workbench.navigation.open` 命令提交 `target: assistant.project`、目标 `projectId` 和 `viewKey: live-dashboard__live-dashboard`。宿主完成授权和项目切换后，View 读取新范围，保持选择器打开并展示右栏看板。选择失败保留原项目和看板。

ChatKit 选择项目时，View 跟随宿主的可信运行范围，更新项目名、可见看板和权限。宿主可能恢复该项目的会话与 Workbench 布局；View 不维护另一份独立的项目筛选状态。

- 项目切换清除旧看板、版本、筛选值和 Assistant 当前目标。
- 旧请求及旧作用域的工具回执不能恢复旧数据；ChatKit 转发 View 事件时携带当前 `scopeRevision`。
- `selectionId` 定位 Artifact；参数保留正式版本、草稿模式或新建状态。刷新和历史导航由宿主恢复目标。
- View 通过 `assistant.context.set` 同步准确的编辑目标。工具仍重新校验项目、Artifact 和草稿修订，不能把上下文当作授权。
- 未选择看板时显示“请先选择要编辑的看板”，保留目标保护，不从历史对话或最近修改时间猜测，也不展示红色技术错误。
- 项目范围由服务端运行上下文提供；看板列表和搜索不接受客户端覆盖 `projectId`。跨项目 Artifact 读取被拒绝。

## 制作操作与权限

主工具栏保留发布草稿、刷新和更多菜单。编辑工作草稿、导入定义、团队分享、版本历史、自动刷新和当前看板删除位于更多菜单，按权限展示。删除仍确认具体看板与草稿修订。状态只显示简短的“草稿 rN / 正式版 vN”，完整标题在路径入口中，更新时间放在更多菜单。

“新建看板”清空当前目标并进入当前项目的新建状态；它本身不保存或发布内容。原有制作、保存、并发冲突和发布确认逻辑保持一致。

| 项目角色       | 看板权限                                         |
| -------------- | ------------------------------------------------ |
| 成员           | 使用已发布版本；未发布的看板不可用，不能读取草稿 |
| 编辑者         | 读取、创建和更新草稿，保留准确的修订基线         |
| 所有者或管理者 | 编辑草稿，并显式发布、分享或删除                 |

归档项目不出现在项目选择器中；已有入口仍执行当前权限，禁止修改。发布和分享不会授予数据源权限，每次查询继续使用访问者自己的授权。

## 内容存储与分享边界

看板定义使用受保护的 Artifact 内容存储。通用项目文件列表和文件工具不能读取其中的草稿；正式版本、草稿引用、内容校验和访问控制由平台 Artifacts 能力统一执行。插件声明 `draft-only` 版本策略，不能通过通用版本上传绕过草稿发布校验。

管理员显式创建的、需要登录的组织分享，可以允许非项目成员读取正式看板定义。该例外仅适用于授权分享链接，不开放草稿、编辑、通用文件或数据源访问，也不能启用匿名分享。

## 配套版本与验证

平台与 SDK 必须提供受保护 Artifact 内容、类型级草稿授权和发布校验；ChatKit 必须保留首次项目消息的宿主回调，并转发带作用域修订的工具事件。先发布配套平台/SDK，再更新插件依赖与锁文件；ChatKit 的对应修复也需随宿主使用的前端版本交付。源码联调通过不代表这些公开包已发布。

2026-10-31 的本地验收已由用户确认：项目双向切换、列表隔离、真实 Assistant 制作和持续修改、草稿与正式版分离、双栏搜索、新建、更多菜单、键盘操作及 480px 窄面板均有验证。Data Xpert 的绑定与查询结果保持一致。插件 186 项测试、构建、dist 和生命周期检查通过；跨页行为及超过 100 项时的标题搜索由自动化覆盖，真实界面数据为单页。此范围不替代生产部署、公开包兼容性或多租户压力验收。
