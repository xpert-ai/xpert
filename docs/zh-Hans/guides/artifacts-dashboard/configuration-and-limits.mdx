## Assistant 与环境配置

1. 使用包含 Analytics、Artifact 草稿、文档宿主与展示 Provider 能力的配套平台、contracts 和 SDK。平台前后端需一起支持相关接口；只升级插件不能补出独立页。
2. 安装 Live Dashboard 与所需来源插件。SQL 来源同时需要对应平台驱动；MySQL/Doris 共用 MySQL 驱动插件。
3. 为 Assistant 连接 `LiveDashboard` 中间件并启用 `live_dashboard`。专用看板 Assistant 可将连接设为 `required: true`；普通 Assistant 保留可选工具的显式启用机制。仅看到 View 不代表 Agent 已获工具。
4. 配置可用模型和技能读取能力，安装插件随附的 `live-dashboard` 技能。文件编写使用平台 `SandboxFile`；脚本另接入 `WorkspaceScriptDataset` 与 `workspace-script-dataset` 技能。
5. HTML 保存预检需要 Browser Runtime 与 `sandbox-browser` 队列；Python/JavaScript 查询另需实现 `compute/node-python/v1` 的受限运行环境和匹配 Runtime Binding。标准图表不依赖 HTML 浏览器预检。
6. 使用外部 schema 管理的环境需应用 `packages/server-ai/src/artifacts/drafts/migrations/20261017-artifact-drafts.sql`。已有 Artifact 首次编辑按当前正式版本建立草稿，无需回填历史草稿。

data-xpert 来源还需要正确的服务地址、受众、Assistant/Workspace 配置及已发布资源和访问者策略。身份由平台生成和转发，不写入 Agent 生成页面。

## 当前限额

| 范围                    | 当前限制                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------- |
| 平台单次 Analytics 查询 | 30 秒、1,000 行；标准化 `rows` JSON 的 UTF-8 内容最多 2 MB                          |
| 看板定义                | 最多 8 个 Binding、24 个控件；标准模式最多 20 张图、20 张表                         |
| HTML 与依赖             | HTML 300 KB；平台最多 8 项依赖，单项 4 MB、合计 8 MB；看板包最大 9 MB               |
| 文档查询桥              | 最多 8 个并发、每分钟 60 次请求；这不是数据源查询配额授权                           |
| Workspace 脚本          | 单文件 64 KB、标准库、UTF-8 输入；最多 8 个文件与 4 个来源别名                      |
| 脚本执行                | 每文件 1 MB、最多 16 次调用、累计调用数据 8 MB、来源输入 4,000 行，受父查询期限约束 |

以上 KB/MB 使用十进制字节单位。当前看板插件只提供 ECharts 和 Three.js 两项图库，Agent 可选择其中一项或两项；平台依赖上限不代表插件提供了 8 项库。

限额是当前实现边界，不是性能承诺。脚本输出仍遵循平台 Dataset 行数和大小限制。中断和期限向上游查询传播；跨来源读取不构成事务快照。

## 状态与处理

| 现象                           | 检查与处理                                                             |
| ------------------------------ | ---------------------------------------------------------------------- |
| View 可见但 Agent 不会创建看板 | 检查中间件连接、ChatKit 工具选择和模型；不要以 View 可见性推断工具权限 |
| 写了 HTML 但没有草稿           | 检查 `dashboard_create_html` / `dashboard_update` 的成功回执和预检结果 |
| 预检失败或图表空白             | 检查 Browser Runtime、声明 Binding、库锁、字段映射和图形容器尺寸       |
| 并发保存或发布冲突             | 保留编辑文件，重新读取最新草稿与正式基准后处理差异                     |
| 分享失败                       | 先确认已有正式版本，再检查来源、成员权限和脚本私有依赖                 |
| 独立页无法打开                 | 检查平台受控命令声明、平台版本、浏览器弹窗设置和正常登录回跳           |
| 最新分享页提示版本变化         | 重新打开以加载一致的正式定义和 Binding                                 |
| 查询时间更新但业务值未变       | 核对来源数据与缓存语义；取数时间不等于业务变更时间                     |

## 已验证范围与未提供能力

本地场景记录覆盖 PostgreSQL、data-xpert、Workspace 脚本、MySQL/Doris 的生成、修改、筛选、刷新和重开，包含 ECharts、草稿定稿、团队成员只读访问及原生 ChatKit 卡片导航。不同记录有不同时间和环境；不能把一次代码检查当作重新执行模型、SSO 或多用户验收。

Three.js 核心对象和打包已验证，真实 SSO 的 GPU/WebGL 页面尚未完成完整验收。Workspace 脚本团队共享被明确禁止；团队成员的 data-xpert 新账号 SSO 不在最近一次分享复验范围。

目前没有统一后台刷新任务、服务端数据变更推送、浏览型草稿历史、多人协同编辑、版本比较/一键回滚、匿名看板分享、独立 REST/JSON Provider 或通用查询结果缓存。HTML 自身可实现轮询，MySQL/Doris 场景已验证该路径。data-xpert 的可用本体适配器由其已发布资源和 Action 决定，不等于新增了直接 REST/语义模型 Provider。

不把 npm 发行、生产镜像、生产部署、多租户压力或公开包版本兼容性视为已验证。功能维护以源码契约和范围明确的验收记录为依据。
