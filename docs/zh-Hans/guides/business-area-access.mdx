用户组管理人员，业务域划分资源范围。将用户组或个人授予某个业务域角色后，同一成员可以在采购域发布资源，在财务域只消费已发布资源。成员仍使用原有的平台角色，无需新增部门实体或为每种跨域组合创建平台角色。

## 三种业务域角色

| 角色                    | 消费本域已发布资源 | 创作和发布         | 管理本域授权 |
| ----------------------- | ------------------ | ------------------ | ------------ |
| 消费者 `consumer`       | 允许               | 不提供             | 不允许       |
| 发布者 `publisher`      | 允许               | 还需资源的创作权限 | 不允许       |
| 域管理员 `domain_admin` | 允许               | 还需资源的创作权限 | 允许         |

业务域角色与平台功能权限共同生效。例如，查看业务域需要 `BUSINESS_AREA_VIEW`，Assistant 创作和分析查询仍需要相应产品功能权限。业务域角色不会自动授予工作空间成员身份、数据源凭据或平台功能。

平台 `BUSINESS_AREA_MANAGE` 权限提供当前组织内的业务域管理能力，权限解释通过 `platformManagement` 单独标识。只有此平台权限允许新建、重命名、移动和删除业务域。域管理员可以管理本域授权，但不能因此调整组织用户组成员、平台角色或业务域结构。

## 在 Cloud 配置授权

1. 在设置页顶部选择目标组织。租户控制台不显示组织业务域入口。
2. 打开 **设置 → 成员与组织 → 业务区域**，选择业务域。
3. 在 **访问授权** 中选择“用户组”或“用户”、授权对象和业务域角色，点击 **保存授权**。再次保存同一主体会更新原授权。
4. 在授权列表中点击 **撤销**，删除该主体在当前业务域的授权。
5. 管理者可通过 **查看成员实际权限** 检查有效角色和来源。普通成员仅看到自己的有效权限和来源，不显示授权管理按钮；业务域基本信息为只读。

候选对象限于当前组织的有效普通用户和人工维护的用户组。系统为资源分享管理的托管组不能用作业务域授权主体。

组成员在 **设置 → 用户组** 中维护。要从用户组核对业务域授权，打开 **设置 → 组织 → 用户组**，选择用户组，即可看到业务域与角色；再选择业务域可管理其授权。查看组维度授权还需要 `ORG_USERS_VIEW`。面板底部的 **刷新** 用于重新读取组授权列表。

## 权限如何合并与撤销

同一业务域内，个人授权和所有有效用户组授权取能力并集，并保留每条授权来源。例如，采购发布组提供 `publisher`，跨域分析组提供 `consumer`，成员同时加入两组时可以消费和发布；退出采购发布组后仍能消费，但发布失效。

组授权保存在组上，不复制为每个成员的个人授权。退组只撤销该组来源；其他组、个人授权和具体资源分享仍按各自规则生效。权限在后续请求中重新计算，用户停用或组织成员资格失效也会阻止组与个人授权生效。

业务域的父子关系仅用于分类，父域授权不会继承到子域。当前没有嵌套用户组、自定义业务域角色或拒绝规则。撤销不删除历史产物，也不自动终止所有已经开始的执行。

## 对资源访问的影响

### Assistant

- 本域授权支持访问已发布 Assistant，不要求加入其创作工作空间。
- 已归属业务域的 Assistant，创作者或创作工作空间成员身份本身不能绕过业务域消费授权。
- 具体 Assistant 的既有分享仍是独立来源，只授权该 Assistant，不扩展为整个业务域的权限。
- 编辑、保存草稿和发布需要原有创作权限及本域发布能力。变更业务域同时检查原域和目标域的发布能力。
- 未归属业务域的资源继续使用原有资源权限；凭据 audience、委托范围和发布状态限制继续生效。

### DataXpert

DataXpert 从 Xpert 平台读取业务域能力和授权来源，使用同一授权记录。业务域列表按当前用户的能力过滤，旧本地个人成员记录不再作为运行时授权后备。

语义模型和指标的消费查询按具体资源校验业务域访问，不要求消费者加入创作工作空间；其他创作接口继续检查工作空间权限。语义模型消费执行发布快照，拒绝直接消费草稿。指标保留发布、认证等业务条件；查询还受查询功能权限、数据源绑定和凭据限制。没有归属业务域的查询资源继续要求工作空间读取权限。

## 示例：采购发布与财务消费

为成员“小李”保留一个普通平台角色，并配置如下授权：

| 用户组     | 授权业务域 | 角色   |
| ---------- | ---------- | ------ |
| 采购发布组 | 采购域     | 发布者 |
| 财务消费组 | 财务域     | 消费者 |
| 跨域分析组 | 采购域     | 消费者 |

让小李加入采购发布组和财务消费组，并仅授予采购创作工作空间的创作权限。将采购助手和财务助手分别归入对应业务域并发布。

| 操作                             | 预期行为                                     |
| -------------------------------- | -------------------------------------------- |
| 访问采购、财务已发布助手         | 两者均可访问                                 |
| 发布采购助手                     | 允许                                         |
| 发布财务助手                     | 拒绝                                         |
| 进入财务创作工作空间             | 未获工作空间授权时拒绝                       |
| 加入跨域分析组，再退出采购发布组 | 采购消费保留，发布失效                       |
| 再退出跨域分析组                 | 采购消费失效，财务消费保留                   |
| 对采购助手另有具体资源分享       | 该分享仍可允许访问采购助手，不恢复域发布能力 |

核对撤销结果时，应查看“有效角色”和全部来源。仅删除一条来源不一定会使最终访问权限消失。

## API 与接入

平台前缀为 `/api/business-area`。所有接口使用认证身份和当前租户、组织上下文，授权请求体不能覆盖租户、组织或操作人。

| 方法与路径                    | 用途                                       |
| ----------------------------- | ------------------------------------------ |
| `GET /access/capabilities`    | 当前用户可查看、发布、管理的业务域 ID 列表 |
| `GET /:id/access`             | 当前用户的有效能力、来源与平台管理标识     |
| `GET /:id/access?userId=…`    | 本域管理者查看指定有效成员的权限           |
| `GET /access/groups/:groupId` | 组维度授权列表；要求组织用户查看权限       |
| `GET /:id/access/candidates`  | 本域管理者可授权的用户与组                 |
| `GET /:id/grants`             | 本域管理者读取授权列表                     |
| `PUT /:id/grants`             | 新建或更新一个主体的授权                   |
| `DELETE /:id/grants/:grantId` | 删除指定授权                               |

组授权请求体示例：

```json
{
  "subjectType": "user_group",
  "userGroupId": "<用户组 UUID>",
  "role": "publisher"
}
```

个人授权使用 `subjectType: "user"` 和 `userId`；`userId`、`userGroupId` 必须二选一。非法角色、额外字段和非法 UUID 会被拒绝。修改授权、读取完整授权列表或查看他人来源均需本域管理能力。

DataXpert 对应入口为 `/api/business-areas/:id/access`、`/:id/access/candidates` 和 `/:id/grants`，写操作转交平台统一判定。共享类型定义在 `@xpert-ai/contracts` 的 `business-area-access.model.ts`。

## 部署与已有授权迁移

1. 部署包含新授权 contracts 的 Xpert 版本，并应用 `core.business-area-access` SQL 迁移后启动 API。已登记为 SQL 管理的表不使用 TypeORM 自动同步代替迁移。
2. DataXpert 使用包含 `IBusinessAreaAccess` 等类型的兼容 contracts 发布版本，更新依赖和锁文件后构建。仅升级平台 API 不会更新 DataXpert 的包依赖。
3. 应用 DataXpert 的 `BusinessAreaGrantMigration1793779200000`，增加旧成员记录的 `migrated_at` 字段。
4. 在启用新授权入口前，由具有平台业务域管理权限的用户调用 DataXpert `POST /api/business-areas/access/migrate`，导入当前组织的有效旧个人授权。
5. 对照上述例子核对消费、发布、退组撤权及权限来源后，再开放业务流量。

导入仅补充缺失的个人授权，已有平台授权优先；成功记录标记迁移时间，可重试。旧表保留用于核对，不参与运行时后备授权。迁移需逐组织执行。

## 排查访问问题

| 现象                             | 核对内容                                                            |
| -------------------------------- | ------------------------------------------------------------------- |
| 看不到业务区域入口               | 是否选择组织，是否具有 `BUSINESS_AREA_VIEW`                         |
| 有消费权限但不能发布             | 是否具有发布者角色、产品功能权限和资源创作权限                      |
| 退组后仍可访问                   | 是否还有其他组、个人授权、平台管理权限或该 Assistant 的具体分享     |
| 父域有权限但子域不可访问         | 为子域单独授权；父子关系不继承权限                                  |
| 可以管理授权但不能修改业务域名称 | 域管理员不包含平台 `BUSINESS_AREA_MANAGE` 权限                      |
| 平台与 DataXpert 结果不同        | 核对登录用户、组织范围、平台连接和 contracts 版本；不要启用旧表回退 |
