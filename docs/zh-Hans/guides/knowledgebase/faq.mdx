FAQ 知识库使用结构化问答条目管理知识。每条条目包含标准问、相似问、反例和答案，检索时返回完整问答内容，并通过引用定位到条目。

## 创建与配置

创建知识库时选择“问答”（`type: faq`），配置模型、向量存储、检索设置和 FAQ 设置。FAQ 不使用普通文档解析、通用分块或 Graph 检索，也不能启用 Wiki。

以下配置仅在创建时指定，已有库中只读，服务端同样拒绝更新 `faqConfig`：

| 字段                                   | 可选值                              | 默认值与作用                                                 |
| -------------------------------------- | ----------------------------------- | ------------------------------------------------------------ |
| `indexMode`                            | `question_only` / `question_answer` | 默认仅索引问题；后者将答案也纳入正向索引                     |
| `questionIndexMode`                    | `combined` / `separate`             | 默认分别编码标准问和相似问；合并模式使用合并文本             |
| `negativeMatchMode`                    | `exact` / `semantic`                | 默认精确排除；语义模式需额外配置阈值                         |
| `semanticThreshold` / `semanticMargin` | 数值                                | 仅语义模式必填，详见[语义反例排除](./faq-semantic-exclusion) |

历史数据缺少反例模式时按 `exact` 处理，不会自动升级为语义模式。

## 条目维护

管理界面提供查询、编辑、启停、删除、导入预览、追加或替换导入、CSV/JSON 导出和重处理。更新和删除使用条目的 `version` 检查并发修改；遇到版本冲突应刷新后重新提交。

| 内容     | 限制                                |
| -------- | ----------------------------------- |
| 标准问   | 最多 500 个字符                     |
| 相似问   | 最多 10 条，每条 500 个字符         |
| 反例     | 最多 10 条，每条 500 个字符         |
| 答案     | 最多 5 个文本块，合计 10,000 个字符 |
| 导入文件 | 最多 10 MiB；支持 CSV/JSON          |

问题规范化使用 Unicode NFKC、空白合并和大小写归一化进行重复与精确匹配检查。反例只排除所属条目，不是整个知识库的黑名单。

## 存储和索引

一个 FAQ 知识库使用托管文档承载条目；一个业务 chunk 是一条 FAQ 的稳定身份。用于检索的向量记录是派生数据，可能一条 FAQ 对应多个向量；模型 Token 限制还可能产生更多物理片段。

- Keyword 投影包含所有正向问题，并按 `indexMode` 决定是否加入答案。
- Vector 投影按 `questionIndexMode` 合并或分别编码；答案索引遵循 `indexMode`。
- 反例不进入正向 Vector/Keyword 投影；语义比较向量由独立缓存维护。
- 保存和正向索引同步有就绪、待同步和失败状态。检索不返回被停用或索引尚未就绪的条目。
- 替换导入先准备新数据，再切换有效内容；失败清理与补偿保持原有内容和向量身份的一致性。

语义预热失败不回滚已成功的 FAQ 保存，但正向索引仍依赖 Embedding 服务，不能把这一规则理解为模型完全不可用时也能正常写入。

## 检索与引用

FAQ 支持 Vector、Keyword、Hybrid。默认使用 Hybrid + Weighted RRF：Vector 权重 0.7、Keyword 权重 0.3、Graph 权重 0。

同一 FAQ 的多向量命中会按稳定业务 ID 去重；分别编码模式会扩充候选窗口，避免同一条目的多个向量占满结果。精确或语义反例排除在完整答案物化与最终重排之前执行。语义模式还有受预算约束的候选补取，详见其独立功能页。

最终提供给 Agent 的内容是完整问答，不是用于索引的投影文本。引用包含 FAQ 条目身份，Cloud 可定位到对应条目；失效引用不应破坏已经加载的列表。

## 管理 API 与权限

接口位于 `/api/knowledgebase/:knowledgebaseId/faqs`：

| 方法与后缀                             | 功能                    |
| -------------------------------------- | ----------------------- |
| `GET /`、`GET /:faqId`                 | 查询列表与单条          |
| `POST /`、`PUT /:faqId`                | 创建与更新              |
| `DELETE /:faqId?version=...`           | 按版本删除              |
| `POST /import/preview`、`POST /import` | 预览与追加/替换导入     |
| `GET /import-template`、`GET /export`  | 模板及全量/指定条目导出 |

这是管理接口，当前 Controller 要求 `KNOWLEDGEBASE_EDIT`，服务层继续执行知识库范围和资源访问检查。通过 Assistant 使用已授权知识的运行时检索是另一条访问路径，不意味着用户可以维护 FAQ。

## 验证范围

仓库包含配置、投影、CRUD、并发版本、引用及检索测试。功能实现完成不等于目标环境验收完成，仍需针对实际部署核对：

- 真实 PostgreSQL Keyword 索引、PGVector/Milvus 的多向量写入/删除、并发及失败补偿。
- 长答案产生大量派生向量时的候选扩窗、延迟和检索排序。
- 浏览器创建、编辑、启停、追加/替换导入、重处理和引用定位。
- 补偿失败后的运维重建与恢复流程。

原实施计划已删除，历史决策与测试记录可从 Git 历史查询。本页不将尚未执行的部署验收标记为通过。
