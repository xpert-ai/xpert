知识库按文件格式选择实际执行的解析器，将转换后的文本、结构和资产交给分块与入库流程。宿主负责发现、配置和校验；外部解析器由插件提供，不根据插件名称推断格式支持。

## 使用流程

1. 在知识库解析设置中，为需要覆盖的格式选择解析器。
2. 按解析器提供的 schema 配置参数；需要服务集成时选择可访问的集成。
3. 上传或批量导入文件。每个文件按自身格式解析，而不是整个批次共用一个策略。
4. 查看解析结果与诊断，再进行分块、索引和检索。
5. 已有文档需要应用新设置时，显式选择重新解析。

插件必须已经安装并实际加载，而且声明支持对应格式。候选列表和运行依赖以当前部署中的元数据为准。

## 配置继承

普通文档入口按以下优先级解析配置：

```text
文档显式覆盖 → 知识库该格式设置 → 系统默认
```

库级配置使用 `parserConfig.parsers[format]`；选择包含 `transformerType`、可选 `transformerIntegration` 和 `transformer` 参数。

```json
{
  "parserConfig": {
    "parsers": {
      "docx": { "transformerType": "builtin" },
      "pdf": null
    }
  }
}
```

`builtin` 是内置解析器选择值。格式键使用规范化文件扩展名。`null` 表示显式恢复系统默认，也覆盖旧 PDF 专项设置；旧 `pdfParser` 在没有相应新配置时仍按兼容逻辑解析。切换策略时清除原策略专属参数和不适用的集成引用。

流水线节点显式指定的解析策略继续按节点配置执行，不能被库级默认值无条件覆盖。

## 内置与插件解析器

内置入口保持已有的按格式处理行为，包括 PDF 默认路径和表格记录处理。外部插件示例包括 MinerU、PaddleOCR-VL、MarkItDown、PDFium、AnyDoc 和 OpenDataLoader PDF；此清单不是任何部署已经安装这些插件的保证。

| 边界             | 行为                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 格式发现         | 仅展示提供者声明支持的格式                                       |
| 集成与参数       | 保存时验证，执行时重新检查可用性与访问范围                       |
| 显式提供者不可用 | 返回未安装、未配置、无权限或执行失败等错误，不静默更换解析器     |
| 运行环境         | 插件按声明使用所需 Runtime、服务和模型，宿主不临时猜测依赖       |
| 解析输出         | 统一为宿主文档、资产及可用结构证据，结构能力取决于提供者实际输出 |

Python、Node、Java 或 OCR 依赖必须由对应插件和部署准备。平台有调用能力，不等于目标环境已经具有可运行的插件包和镜像。

## 表格、图片与结构

Excel/CSV 原生记录模式保留表头、字段选择、按行处理和表格元数据语义。仅输出 Markdown 的解析器不能被当作支持相同结构化表格能力。

图片理解与文件解析是不同阶段。OCR/VLM、扫描页转录和普通图片描述的执行取决于解析器输出及图像配置，不能假设增加解析器就需要重复识别。页码、图片和来源证据应沿转换结果传递；没有提供的布局证据不由分块器凭名称补造。

## 重新解析、重新分块与缓存

- 修改库级设置主要影响后续导入，不自动重建已有文档。
- 重新解析重新执行转换，可以调用外部服务及模型。
- 仅重新分块复用已保存的解析结果；缺少可用快照时应按对应入口的校验处理，不能把一次外部解析伪装为纯分块。
- 解析配置和实际策略参与转换身份，切换策略或参数后不能误用旧结果。
- 解析快照与分块缓存是不同层次；[分块策略](./chunking)记录实际选择、算法修订和来源范围。

## 部署和验证范围

按已安装提供者核对声明格式、集成权限、Runtime 健康和真实文件结果。对混合格式、文档覆盖、插件缺失、超时、缓存失效及重新分块分别验收。

功能实现及宿主接线已具备。目标环境仍需单独完成插件包和 Runtime 镜像发布、部署绑定、服务/模型连通性以及真实内容验收，不能由安装记录或本地构建结果替代。

重点验收包括：

- AnyDoc 的实际声明格式、扫描页转录和资产映射；OpenDataLoader PDF 的受管 Java 环境、OCR 依赖与解析结果。
- 原生 PDF 与扫描 PDF、DOCX、Markdown/TXT，以及所选插件实际支持的其他格式；逐项检查正文、页码、图片、表格和来源证据。
- 混合批次、文档覆盖、重新解析、仅重新分块和取消/失败后的临时资源清理。
- 需要视觉模型的路径是否正确使用目标模型，识别结果是否满足业务质量要求。
