分块将解析结果转换为检索单元。普通文本支持自动、结构感知、Markdown 标题和长度策略，预览与正式处理共用执行入口。策略选择本身不调用模型。

## 选择策略

| 提供者 ID             | 行为                                       | 大小语义                         |
| --------------------- | ------------------------------------------ | -------------------------------- |
| `auto`                | 根据显式格式和结构选择实际策略             | 随所选策略变化                   |
| `structure-aware`     | 尽量保留章节、段落、表格、列表、代码和公式 | 目标大小，结构单元可影响实际边界 |
| `markdown-recursive`  | 使用已有 Markdown 标题递归算法             | 保持旧策略语义                   |
| `recursive-character` | 按长度、分隔符与重叠切分                   | 保持旧策略语义                   |

未指定策略的普通分块默认 `auto`，已有显式策略及参数保持有效。结构感知配置缺省 `chunkSize` 为 1000、`chunkOverlap` 为 100；它们不是 Embedding 模型的 Token 上限。

## 自动决策

自动策略先按已知文档身份归组，再检查解析结果中的格式与结构：

1. 有表格、列表、代码或公式等复杂结构，选择 `structure-aware`。
2. 全部标题符合旧算法支持的 ATX 1–3 级标题，选择 `markdown-recursive`。
3. 有其他明确标题或布局标题，选择 `structure-aware`。
4. 普通文本选择 `recursive-character`。

不能用提供者名称或显示名称推断结构。输入缺少所需格式声明时会报告问题；显式布局依靠页码、阅读顺序和结构字段。

## 结构保护与大小限制

结构感知策略保留章节路径，并在超长结构内部寻找续片边界：表格按行、列表按项、代码按行继续切分。重复标题、表头和代码围栏也占用预算。极小预算下可能需要继续拆分，不能保证任意表格、列表或代码块始终完整。

长表优先保留完整数据行，必要时减少重复上下文；如果数据行本身超过 Token 硬上限，仍可能拆行。来源正文和为便于阅读而重复的上下文分别记录。

`maxChunkTokens` 允许 0–8192，0 表示关闭该显式上限。流水线节点显式 Token 配置优先，0 也可以覆盖继承值。持久化前仍有实际 Embedding 模型预算检查，因此预览中的一块不保证最终只产生一个向量片段。

当前结构分析输入上限为 500 万字符、输出上限为 10,000 块；轻量预览输入限制为 10 万字符。这些限制用于有界处理，不是模型上下文大小。

## 预览和来源证据

预览记录请求策略、实际策略、选择原因、结构统计、章节路径、续片及降级信息。分块 `chunking` 元数据保存算法修订、输入指纹及来源/上下文范围。

来源映射不完整或旧算法无法给出精确范围时，会标记粗粒度来源；不能将重复标题和表头误当作新的原文证据。算法修订参与处理缓存身份；文档级诊断变化不应单独导致未变分块重新索引。

## 适用边界

- 普通分块和已有父子分块是不同路径。已有 `parentId`、父子类型、Sheet 或特殊字段投影不能静默送入新通用策略。
- `searchContent` 与正文不同的字段投影需要保留自己的语义，不能随意改写成普通正文片段。
- HTML/图片表格、复杂合并单元格、跨片段续表及丢失的解析结构不承诺完整恢复。
- 文档解析质量决定可供分块使用的结构。分块策略不能补回转换器已经丢弃的内容。
- 历史样例对 CRLF 标题、DOCX 自动编号及 PDF 非文本片段有单独记录；本次文档转换未重跑这些格式样例，不能据此宣称全面格式验收完成。
