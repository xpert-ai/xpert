语义反例排除用于识别“表达不同但含义接近反例”的查询。它只作用于反例所属的 FAQ，覆盖 Vector、Keyword 和 Hybrid，不改变普通文档、Wiki、Graph 或外部知识库的检索行为。

## 配置与判定

创建 FAQ 时选择 `negativeMatchMode: semantic`，同时填写：

| 参数                | 合法范围 | 创建界面初始值 |
| ------------------- | -------- | -------------- |
| `semanticThreshold` | `[0, 1]` | 0.85           |
| `semanticMargin`    | `(0, 2]` | 0.05           |

服务端要求有限数值。参数和模式创建后不可修改，旧库不会自动切换。界面初始值不是经过通用模型校准的准确率承诺，余弦相似度也不是概率。

判定按以下顺序进行：

1. 查询规范化后精确匹配本条反例：排除。
2. 精确匹配本条标准问或相似问：保留。
3. 本条无反例：保留，不进行语义比较。
4. 其他情况，使用活动 Embedding 模型分别编码正向问题与反例，并计算最高余弦相似度。

```text
positiveScore = max(similarity(query, each positive question))
negativeScore = max(similarity(query, each negative question))
exclude = negativeScore >= threshold
          AND negativeScore - positiveScore >= margin
```

例如，“不退货只退款”可以作为“退货退款流程”的反例，但不影响其他条目回答“仅退款条件”。分数接近时保留当前候选；保留仅表示通过本次排除检查，后续相关性筛选和重排仍可能淘汰它。

正向比较使用标准问和相似问，不使用答案向量、Keyword 分数或 RRF 分数。不额外调用聊天模型。Keyword-only 检索开启此能力后也需要可用的 Embedding 模型。

## 缓存与预热

FAQ 保存及正向索引成功后，后台预热独立的问题比较向量。预热提交或执行失败不回滚已保存的条目；查询遇到缓存缺失时补算需要的文本。

缓存身份包含租户、组织、知识库、模型身份和问题内容。当前实现使用共享缓存，TTL 为 30 分钟；同一进程合并进行中的相同计算，但没有跨进程计算锁，多个副本仍可能重复编码。

后台任务校验当前用户与组织、条目版本、内容哈希、启用状态及索引状态。过期任务不能重新启用删除或停用的条目。请求内还缓存单条 FAQ 的判定，内容变化会重新判断，融合排名不会作为判定缓存复用。

## 候选补取和预算

```text
召回分支 → 恢复当前 FAQ / 去重与融合 → 反例排除
          → 合格候选不足时扩大窗口
          → 物化完整答案 → 最终重排 → Top K
```

Hybrid 每轮从最新分支结果重新融合，不累计上一轮 RRF 分数。已耗尽分支保留结果，仅扩充仍可补取的分支；零权重分支不执行。

| 限制               | 当前实现                   |
| ------------------ | -------------------------- |
| 外层补取轮数       | 最多 6 轮                  |
| 候选槽预算         | 20,000，跨补取调用累计计数 |
| 语义比较           | 最多 400 次                |
| 待编码问题文本预算 | 4,000                      |
| 请求预算时间       | 60 秒                      |
| 单次模型等待       | 30 秒                      |
| 向量编码批量       | 32 条文本                  |
| 预热 Worker        | 并发 2，最多 3 次尝试      |

请求预算是调用前检查，不是整条链路的精确墙钟截止时间；已经发起的操作另有超时。达到预算后只返回已经通过检查的候选，允许不足 Top K。最终重排阈值导致结果不足时，不重新启动补取或降低阈值。

## 故障和诊断

- 缓存读取失败按未命中处理；写缓存失败仍可使用本次有效向量。
- 模型失败、超时、空向量、非有限数值或维度不匹配会明确报错，不伪装成“模糊匹配，保留”。
- 正向召回索引与比较缓存是不同数据，不会因为给反例编码而将其加入正向索引。
- 检索诊断包含比较、排除、缓存命中、复用、编码及预算信息；排查错误时区分缓存故障与模型故障。

## 实现与验收边界

实现位于 `packages/server-ai/src/knowledgebase/faq/` 的 `faq-semantic.service.ts`、`faq-semantic-match.ts`、`faq-semantic-cache.service.ts`、`faq-semantic-prewarm.ts` 和 `faq-retrieval-budget.ts`；补取编排位于 `queries/handlers/knowledge-search.handler.ts`。

真实模型需要用分离的校准集与验收集评估误排、漏排和延迟，尤其覆盖否定、条件变化、组合意图及精确正例。模拟向量测试不能证明模型效果。

目标环境仍需记录以下结果：

- 固定模型和参数后，保留查询的误排率、反例改写的漏排率及过滤后 Recall@K。
- 预热成功、预热失败后的冷缓存、热缓存和多轮 Hybrid 补取的 p50/p95 延迟、模型调用量和向量化用量。
- 新建时参数提交、编辑态锁定、FAQ 维护及最终检索结果的浏览器验收。
