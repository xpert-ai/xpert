---
title: 'MinIO 文件存储'
---

MinIO 是 `@xpert-ai/plugin-draft` 中的组织级 FileStorage provider。通过平台插件生命周期部署，确认运行后，在“设置 → 插件 → Draft File Storage Providers”的 MinIO 分组配置。同包还注册 S3、RustFS、Wasabi 和 OSS。使用与宿主匹配的实际构建版本；draft 包不代表已有对应 npm 发布版本。

## 存储边界

`FILE_PROVIDER=MINIO` 只切换 **FileStorage**。Workspace Files、应用数据、ArtifactContent、Artifact 草稿/版本和 Sandbox 工作区仍使用本地 POSIX Volume，必须为 API、worker 和 sandbox 保留相应的持久共享存储。文件 Analytics 通过 Workspace Files 读取，并不直接查询任意 S3 对象。详见[存储验证与迁移约束](../../development/minio-storage-foundation.md)。

## 配置

优先级依次为：加密保存的 `PluginInstance.config.minio`、插件环境默认配置、provider 默认值。环境解析保留在通过 Nest Config 注册的 `file-storage.config.ts`，业务服务不读取环境变量。

| 字段                | 环境变量                    | 含义                                                                  |
| ------------------- | --------------------------- | --------------------------------------------------------------------- |
| `endpoint`          | `MINIO_ENDPOINT`            | 服务端可达的 HTTP(S) 地址                                             |
| `signedUrlEndpoint` | `MINIO_SIGNED_URL_ENDPOINT` | 生成签名时使用的浏览器可达地址，须指向相同 bucket 并使用相同凭据      |
| `bucket`            | `MINIO_BUCKET`              | 预先创建的 bucket；私有文件使用私有桶                                 |
| `region`            | `MINIO_REGION`              | 签名区域，默认 `us-east-1`                                            |
| `forcePathStyle`    | `MINIO_FORCE_PATH_STYLE`    | 默认 `true`；虚拟主机模式需要 bucket 对应的 DNS/TLS 路由              |
| `signedUrlExpires`  | `MINIO_SIGNED_URL_EXPIRES`  | 1–604800 整数秒，默认 3600                                            |
| `publicUrl`         | `MINIO_PUBLIC_URL`          | 显式的匿名公开 URL 前缀，优先于签名                                   |
| `rootPath`          | `MINIO_ROOT_PATH`           | 旧 multipart key/path helper 前缀；统一上传目标自行生成带作用域的 key |

凭据通过加密插件配置或部署 secrets 注入。Access key 别名为 `MINIO_ACCESS_KEY_ID`、`MINIO_ACCESS_KEY`、`MINIO_ROOT_USER`；secret 别名为 `MINIO_SECRET_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_ROOT_PASSWORD`。

私有桶使用反向代理时，`endpoint` 配置服务端地址，`signedUrlEndpoint` 配置外部 HTTPS 地址，**不设置 `publicUrl`**。不能在生成签名后替换 URL 主机名，因为主机也参与签名。代理须保留 host/path/query 并访问同一个桶。TLS 证书验证保持开启，本次未增加跳过证书验证的开关。

其他兼容 provider 对应 `S3_SIGNED_URL_ENDPOINT`（或 `AWS_SIGNED_URL_ENDPOINT`）、`RUSTFS_SIGNED_URL_ENDPOINT`、`WASABI_SIGNED_URL_ENDPOINT`。

已认证的租户设置 `fileStorageProvider` 可覆盖部署默认值。保存设置后会使该租户的设置缓存失效，后续上传重新加载 provider。多实例部署须共享缓存；更改默认值不会迁移已有对象。

## 上传

确认 provider 在当前组织运行后，才设置 `FILE_PROVIDER=MINIO`。已认证的公开上传接口仅接收一个由服务端管理的目标：

```bash
# 使用应用正常的已认证客户端/会话。
curl -X POST http://localhost:3000/api/files/upload \
  -F 'file=@./report.csv' \
  -F 'targets=[{"kind":"storage"}]'
```

provider、directory、filename 和多目标选择仅供可信服务端命令使用，不能通过公开 HTTP 参数指定。统一上传将 MIME 写入对象 `Content-Type`；直接调用 provider 可传入第三个参数 `{ contentType }`，默认 `application/octet-stream`。上传结果保留精确对象 key。

对象签名 URL 在过期或对象删除前属于持有者访问凭据。可撤销 Artifact 分享须经过平台 Artifact 链接与授权，不能用对象 URL 替代。不要把签名 URL 保存为可迁移数据集或 Artifact 身份。
