title: '文档来源导入'
description: '通过项目连接导入飞书文档文本副本，保留来源并在 Xpert 内协作。'
---

空间通过平台的文档来源接口读取外部文档，具体适配由连接器插件提供。当前已实现飞书新版文档的文本副本导入：导入后得到项目内的 Markdown 页面，可在 Xpert 内编辑、引用、检索和协作。

导入不是双向同步。在 Xpert 修改副本不会写回飞书，飞书原文变化也不会自动覆盖已经导入的内容。

## 使用前提

- 安装提供文档来源能力的飞书连接器插件，以及兼容的 Spaces 与 Markdown 编辑器插件。
- 在目标项目的连接配置中完成飞书授权，确认连接显示“已连接”。
- 授权的飞书账号必须能阅读测试文档；浏览器当前登录的账号不一定等于连接实际使用的账号。
- 当前 Xpert 用户需要有目标项目的编辑权限，项目不能已归档，所用 Assistant 需要连接该项目。

当前文档来源使用共享连接。可读取哪些飞书文档取决于该连接的授权账号，而不是每个项目成员各自的飞书账号。导入会把内容复制给目标项目的授权成员，请在确认前核对文档与项目的共享范围。

## 导入流程

1. 在目标项目的协作空间中选择“新建”→“从文档平台导入”。
2. 选择飞书文档来源。如果刚完成授权，使用“重新检查连接”。
3. 搜索文档标题，或粘贴文档链接并预览。
4. 核对标题、文本预览、来源和格式降级提示，确认复制到当前项目。
5. 选择“导入文本副本”。成功后打开新页面，在 Markdown 编辑器中查看。
6. 通过内容条目的来源信息回查原文、导入版本和导入时间。

支持 HTTPS 的 `*.feishu.cn` 与 `*.larksuite.com` 文档地址：

```text
https://<tenant>.feishu.cn/docx/<document-token>
https://<tenant>.feishu.cn/wiki/<node-token>
```

知识库 `/wiki/` 链接必须指向新版文档（docx）。它不表示已经支持整个飞书知识库或所有节点类型。

## 查找与内容范围

| 能力           | 当前范围                                                     |
| -------------- | ------------------------------------------------------------ |
| 空查询列出     | 飞书云盘根目录，不递归遍历文件夹                             |
| 标题关键词搜索 | 最多处理前 199 个新版文档搜索结果                            |
| 直接链接       | 新版文档 `/docx/`，或目标类型为 docx 的 `/wiki/` 节点        |
| 内容读取       | 最多 100,000 个 UTF-8 字节的纯文本                           |
| 导入结果       | 项目中的独立 Markdown 文本副本                               |
| 格式提示       | 不保留图片、附件、公式、页面布局、表格结构、评论和富文本样式 |

外部文本按字面内容编码，不把其中的 Markdown 或 HTML 自动变成可执行或额外的富文本功能。需要图片、表格或公式时，可以在导入后的页面中使用[编辑器插入功能](/zh-Hans/guides/spaces-markdown)补充。

## 一致性与来源记录

预览和确认导入之间，服务端会重新读取原文并核对版本与内容 hash。原文已经变化时要求刷新预览，不导入用户尚未确认的新版本。读取过程中也会核对元数据，避免把修改中的两版文档拼在一起。

同一次导入请求支持幂等重试；完成后重复提交返回已创建的资源，不生成重复副本。新的请求可有意创建另一份副本。目标文件冲突不会覆盖已有内容。

来源记录包含提供者、文档标识、原文链接、版本、hash、导入时间和降级提示，不向前端暴露连接密钥。复制完成后，远端内容变化或远端权限撤销不会自动删除本地副本；本地访问继续由项目权限决定。

## 验收步骤

建议使用专用测试文档，并安排两个有编辑权限的项目账号：

1. 在飞书原文中写入一段可识别文本，通过搜索和直接链接分别验证能找到并预览它。
2. 导入并检查页面正文、来源、项目文件及重新打开后的内容。
3. 两个账号从连接同一项目的 Assistant 打开该资源，分别编辑不同段落，确认双方看到修改与在线状态。
4. 等待文件保存，再刷新两个编辑器，确认内容一致；断线恢复后再检查更新补齐。
5. 使用只读项目成员确认不能修改，使用无权限账号确认不能读取资源。
6. 在飞书修改原文，确认 Xpert 副本没有被自动覆盖；预览后再改原文，应要求刷新预览才能导入。

这些步骤是部署后的验收方法，不是对任意安装环境都已完成测试的声明。最终发布包组合仍需按[部署检查清单](/zh-Hans/architecture/spaces-content#发布与部署)验收。

## 常见问题

| 现象               | 检查项                                                                   |
| ------------------ | ------------------------------------------------------------------------ |
| 已连接，但无法阅读 | 检查连接授权账号是否能打开原文，以及应用权限范围；不能仅凭浏览器账号判断 |
| 搜索不到文档       | 空查询只列根目录，关键词结果有数量上限；可尝试直接 `/docx/` 链接         |
| `/wiki/` 不支持    | 检查节点是否为新版文档，当前不导入表格、多维表格或其他节点类型           |
| 确认时提示来源变化 | 刷新预览，重新核对后导入                                                 |
| 导入按钮不可用     | 检查项目写权限、归档状态、连接可用性及预览是否成功                       |
| 导入缺少图片或排版 | 当前读取的是纯文本，原文保留在飞书，副本可在 Xpert 继续补充              |

## 扩展其他平台

平台暴露通用文档来源契约，连接器实现来源列表、搜索和读取，Spaces 复用相同的预览及确认流程。飞书凭据、API 域名及格式转换留在连接器内，空间视图不依赖飞书专用 SDK。

语雀、WPS、腾讯文档、钉钉等适配器，以及远端回写、双向同步、定时拉取、原生编辑器嵌入，均需单独设计、授权并验证；它们不是本次功能交付的一部分。接口边界见[架构与扩展](/zh-Hans/architecture/spaces-content#文档来源适配)。
