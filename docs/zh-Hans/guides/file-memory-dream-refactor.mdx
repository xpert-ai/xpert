---
title: 'Xpert Memory：长期记忆'
description: '为助手开启跨会话记忆，在 Workbench 或 Studio 管理笔记，并用原始会话核对自动复核和 Dream 的修改。'
---

Xpert Memory 让助手在后续对话中继续使用已经确认的偏好、规则和参考资料。例如，用户明确说过「仓库交接清单每天 18:00 归档」，下次询问归档时间时，助手就能从记忆中找到这条规则。每条笔记都有标题、摘要和正文；有会话来源时，还可以追溯到原始消息。

## 开启并找到记忆库

1. 在**助手设置 → 记忆与上下文**中开启**长期记忆**，保存草稿并在 Studio 发布。这个开关会把内置文件记忆中间件接到主智能体。旁边的**会话总结**用于压缩当前对话中的早期消息，可独立配置。
2. 在 **Workbench** 的视图列表中打开**长期记忆**，或在 **Studio** 侧栏打开**记忆**。两个入口默认显示**记忆库**。在这里保存笔记会立即更新运行数据，无需再次发布助手。
3. 核对当前助手和项目。个人隔离的助手按用户保存记忆，共享助手使用共享范围，项目中的助手使用项目范围。要从两个入口核对同一条记录，请使用同一账号和助手，并在 Workbench 切到非项目会话，与 Studio 的助手范围对齐。

## 启用标准问答

在**助手设置 → 能力**开启**标准问答**并发布。单独启用这项能力即可在 Workbench 和 Studio 打开记忆库。开启标准问答的智能体须使用默认文本输出。同一助手的其他智能体仍可使用结构化输出。在记忆库中打开一条笔记，填写标准问题、可选的等价问法，并选取笔记正文中的原文作为答案，确认后生效。主智能体在新私聊消息中命中任一已核准问法，就直接发送一次笔记原文，无需主模型生成答案。会话达到压缩门槛时仍照常整理历史消息。其他问法继续正常处理。编辑或归档笔记会立即使原审批失效，即使改回原文也要重新确认。

## 哪些内容值得记

判断的依据是这条信息会改变未来的哪项决定。「以后所有值班交接都列出未关闭的告警」可以指导后续交接；「这次请列出告警」只适用于当前任务。助手会从相关笔记中召回摘要，需要具体条件或原文时再读取正文。用户在当前回合给出的新说明优先。

| 记忆类型 | 适合保存的内容                                 |
| -------- | ---------------------------------------------- |
| 用户偏好 | 用户希望后续周报都先列风险，再列进展。         |
| 反馈     | 用户纠正了交接方式，并明确以后都按新方式处理。 |
| 项目规则 | 项目组已确认仓库交接清单每天 18:00 归档。      |
| 参考资料 | 后续查找值班安排时应使用哪份排班表。           |

你可以明确说「请记住这条规则」，让助手调用 `memory_write` 直接保存。有编辑权限时，也可以在**记忆库**用 **+** 新增笔记，或选中笔记后编辑、归档。已归档的笔记退出日常召回，可用状态筛选找回查看。手工创建的笔记可能没有会话来源。

## 查看一条自动复核记录

即使没有明确要求保存，助手也可以在回合结束后提出新增、纠正或归档笔记的建议。建议须指出未来用途，并引用该回合的用户原话或工具输出。私人会话的自动复核适用于已登录普通用户的个人隔离助手或项目范围；共享助手卷不会自动收录私人会话的这类建议。

1. 打开**复核记录**，选择与本次纠正对应的条目。明确纠正一条已有笔记的候选，入队约 **15 秒**后可开始复核；其他候选约 **30 分钟**后可开始。实际完成时间取决于队列和模型。
2. 对照**原笔记**、**拟写入的笔记**和**复核理由**。展开**原始会话证据 → 查看原文**，核对是谁说的、适用于什么场景。操作性结论需要同一回合、同一次执行的工具结果支持；助手自己转述过这句话，并不能给它增加证据。
3. **已应用**表示建议已写入。**证据不支持**、**待核实**或**缺少证据**会保留当前内容。**笔记已更改**表示候选产生后又有人修改了笔记，复核保留较新的版本。有编辑权限时，可以打开当前笔记修正。

## 运行全库 Dream 整理

有管理权限时，打开 **Dream 整理 → 运行 Dream**。Dream 直接使用当前助手主智能体的模型；主智能体继承助手模型时，就使用继承的模型。它分批对照当前笔记和可核验的原始消息，检查每项建议的引文和笔记版本，再纠正内容或归档明确过时的笔记。缺少依据的细节列入报告的**待确认**。

**设置 → 运行前检查整理条件**控制本次请求是否执行。默认开启。首次运行直接整理，此后从上一次「完成」或「部分完成」起计算，以下三项默认条件须同时满足：已过 **30 分钟**、至少 **1 条**笔记新增或更新、至少 **1 个**会话产生了记忆信号。条件不满足时，记录显示**已跳过**并列出原因。达到门槛本身不会发起运行。

## 示例：用原话核对归档时间

1. 在一条带会话来源的测试笔记中，先展开**查看原文**，找到用户的完整更正「仓库交接清单每天 18:00 归档。」然后手动把这条笔记的摘要和正文都改为 20:00。
2. 运行 Dream。若仅为验收而且没有新的会话信号，可先在测试助手中临时关闭运行前检查，验收结束后恢复原设置。
3. 在**整理记录**点击本次运行时间，核对下面三项，再回到**记忆库**确认摘要和正文。需要从另一端验证时，在相同范围打开同一运行时间的记录。

| 报告位置        | 应看到的结果                                                           |
| --------------- | ---------------------------------------------------------------------- |
| 整理前 → 整理后 | 「仓库交接清单每天 20:00 归档。」改为「仓库交接清单每天 18:00 归档。」 |
| 原文引文        | 能在原始用户消息中逐字找到 18:00 的完整规则。                          |
| 待确认          | 使用哪个时区仍需确认。笔记正文和摘要只保留原话给出的规则。             |

此次整理可以显示**部分完成**：时间纠正已经写入，时区问题仍然待确认。点开报告即可分别查看实际变更和待确认项。
