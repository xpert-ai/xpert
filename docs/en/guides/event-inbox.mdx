---
title: 'Event Inbox'
description: 'Find events from the Assistant workbench or either personal Bosi entry, read their outcomes, and open a related conversation.'
---

The Event Inbox records business events that a connected plugin delivers to an Assistant. Each event has a receipt. For example, after a supplier revises a quote, you can check whether delivery slipped, inspect the resulting risk, and return to the conversation in which that revision was parsed.

## Open the inbox

Sign in and select an organization. All three entries open the same built-in view. A given event has the same receipt ID and processing status in each entry.

| Entry               | Where to open it                                                                         | Scope                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Assistant workbench | Open the Assistant and choose **Event Inbox** from its workbench menu.                   | Your events for that Assistant.                                                                    |
| Bosi Web            | Choose **Bosi Agent → My events** in the sidebar. The page route is `/chat/event-inbox`. | Your accessible events across Assistants in the current organization. You can filter by Assistant. |
| Bosi App            | Choose **My events** from the user menu.                                                 | The same personal scope as Bosi Web. You can open it before selecting an Assistant.                |

The platform starts with bindings for the current tenant, organization, and **user acting on the binding**. It checks your access to the published Assistant, authoring access to its workspace, and project access for a project-bound Assistant. Two members of the same organization can therefore see different events. Category counts, search, details, and retry all use that same scope.

## Find an event

1. Choose a category in the left pane, such as **Procurement**. The center pane lists the newest receipts first. Each row shows its specific type and icon. For example, the Feishu category includes both **Incoming message** and **Card action**.
2. Search for a type label, business reference, source event ID, or receipt ID. Sources can also support search by business title. In the personal view you can narrow results to one Assistant. Choose **Needs attention** to see blocked and isolated receipts.
3. Select a row to see when the event occurred, when it arrived, and its result or reason. Expand a result to inspect the business fields supplied by the plugin. **Technical details** includes the receipt ID for troubleshooting. On narrow screens you can return from the detail panel to the list.

When a source is uninstalled or has no display definition for a historical version, accessible receipts appear under **Uncategorized** with their original type key. For an empty list, check your organization, Assistant, and filters, then confirm that capture is enabled for the source. Reading a receipt leaves its processing status unchanged.

## Interpret the outcome

| Status               | What you can do                                                                                                                                                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pending / Processing | The platform has received the event and is queuing or processing it. Refresh to check progress.                                                                                                                                           |
| Waiting to retry     | Processing did not finish. The platform will try again after a backoff period.                                                                                                                                                            |
| Handled              | The plugin recorded a business operation and a result reference. Consult the review run or channel record to check whether a review finished or a card arrived.                                                                           |
| Ignored              | A business rule ended processing. For example, the first quote establishes a baseline.                                                                                                                                                    |
| Blocked              | Read the reason. Authorization may have changed, a card may have a different operator, or a delivery date may be unclear.                                                                                                                 |
| Isolated             | Investigate the cause. If **Retry** appears, confirm to requeue the same receipt. The binding must still be enabled at the receipt's revision, the source must support its type and version, and the receipt must have no final decision. |

## Open a conversation

Select an event and choose **Open conversation** in its details. All three entries open the linked chat thread. The plugin identifies the conversation for this particular event. The platform checks your read access, tenant, organization, published Assistant family and applicable project, and verifies that the conversation has a thread. When you click, the host looks up the receipt again. Refresh the details if your access changed in the meantime.

| Event                        | Conversation opened                                                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Code Review                  | The readable review associated with this PR automation run, or the conversation for this workflow diagnosis. The run result can appear before the review has created a conversation. |
| Procurement Quote Comparison | The conversation in which **this quote revision** was parsed. Historical revisions without that reference can still show a receipt and an available risk result.                     |
| Feishu                       | The Xpert conversation associated with this message or card dispatch. A new conversation can be linked through a successful outbound record for the same Handoff run.                |

The button is hidden if the source has no explicit association, the conversation lacks a usable thread, or you lack read access. A Feishu chat ID or a procurement case number alone cannot identify a chat thread for this action.
