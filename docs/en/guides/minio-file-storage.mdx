# MinIO File Storage

MinIO is an organization-scoped provider in `@xpert-ai/plugin-draft`. Deploy the package through the platform plugin lifecycle, verify it is running, then configure the **MinIO** section of **Settings → Plugins → Draft File Storage Providers**. The package also registers S3, RustFS, Wasabi and OSS. Use the version actually built for your host; the draft package is not a promise of a published npm release.

## Storage boundary

`FILE_PROVIDER=MINIO` selects the default **FileStorage** provider only. Workspace Files, app data, ArtifactContent, Artifact drafts/versions, and Sandbox workspaces still use POSIX Volumes. Their files must remain on durable storage shared with the relevant API/worker/sandbox processes. File Analytics uses Workspace Files; it does not query arbitrary S3 objects. See [storage verification and migration constraints](../../development/minio-storage-foundation.md).

## Configuration

Encrypted `PluginInstance.config.minio` overrides plugin-local environment defaults, followed by provider defaults. Environment parsing stays in `file-storage.config.ts`, registered through Nest Config; business services do not read these variables.

| Setting             | Environment default         | Meaning                                                                                    |
| ------------------- | --------------------------- | ------------------------------------------------------------------------------------------ |
| `endpoint`          | `MINIO_ENDPOINT`            | Server-reachable HTTP(S) endpoint                                                          |
| `signedUrlEndpoint` | `MINIO_SIGNED_URL_ENDPOINT` | Browser-reachable endpoint used **while signing**, for the same bucket and credentials     |
| `bucket`            | `MINIO_BUCKET`              | Pre-provisioned bucket; use a private bucket for private files                             |
| `region`            | `MINIO_REGION`              | Signing region, default `us-east-1`                                                        |
| `forcePathStyle`    | `MINIO_FORCE_PATH_STYLE`    | Default `true`; virtual-host mode requires bucket DNS/TLS routing                          |
| `signedUrlExpires`  | `MINIO_SIGNED_URL_EXPIRES`  | Integer seconds, 1–604800, default 3600                                                    |
| `publicUrl`         | `MINIO_PUBLIC_URL`          | Explicit **unsigned public** URL base; takes precedence over signing                       |
| `rootPath`          | `MINIO_ROOT_PATH`           | Legacy multipart key/path helper prefix; unified storage targets use their own scoped keys |

Supply credentials through encrypted plugin configuration or deployment secrets. Supported access-key aliases are `MINIO_ACCESS_KEY_ID`, `MINIO_ACCESS_KEY`, `MINIO_ROOT_USER`; secret aliases are `MINIO_SECRET_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_ROOT_PASSWORD`.

For a private bucket behind a proxy, set `endpoint` to the server endpoint, `signedUrlEndpoint` to the external HTTPS endpoint, and **leave `publicUrl` unset**. Do not rewrite the host of a generated signed URL: the host is signed. The proxy must preserve host/path/query and reach the same bucket. TLS certificate verification remains enabled; this change does not add an insecure TLS bypass.

For other compatible providers the equivalent signing variables are `S3_SIGNED_URL_ENDPOINT` (or `AWS_SIGNED_URL_ENDPOINT`), `RUSTFS_SIGNED_URL_ENDPOINT` and `WASABI_SIGNED_URL_ENDPOINT`.

The authenticated tenant setting `fileStorageProvider` can override the deployment default. Saving tenant settings invalidates that tenant’s settings cache after persistence, so subsequent uploads reload the provider. Multi-instance deployments should share their cache; changing the default does not migrate existing objects.

## Upload

Set `FILE_PROVIDER=MINIO` only after the provider is running in the active organization. The authenticated public upload endpoint accepts exactly one server-managed target:

```bash
# Use the application's normal authenticated client/session.
curl -X POST http://localhost:3000/api/files/upload \
  -F 'file=@./report.csv' \
  -F 'targets=[{"kind":"storage"}]'
```

Provider, directory, filename and multi-target selection are trusted server command options, not public HTTP inputs. The unified upload forwards MIME to object `Content-Type`; direct provider writes may pass `{ contentType }` as the third `putFile` argument and otherwise default to `application/octet-stream`. Upload results preserve exact object keys.

Signed object URLs are bearer access until expiry or object deletion. Revocable Artifact sharing must use platform Artifact links and authorization, not an object URL. Never persist signed URLs as portable dataset or Artifact identities.
