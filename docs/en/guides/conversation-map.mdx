title: 'Conversation Map'
description: 'Browse project conversations and discussion branches, search message history, and locate exchanges from Map, List, or Growth tree.'

Conversation Map is a built-in Assistant Workbench view for browsing existing conversations, tracing discussion origins, searching history, and returning to chat. It offers three presentations: **Map, List, and Growth tree**.

## Opening the view and choosing a scope

Open **Conversation Map** from the Assistant's Workbench menu. It opens in a separate tab without additional middleware configuration. The view opens on demand, rather than automatically when entering a chat.

Without saved preferences, the view selects the current project and opens **Map → Branch paths**, vertically arranged with compact nodes. Previous versions and shared history are hidden. The project selector lists accessible projects within the current Assistant's version family. Select **Unassigned** for conversations without a project.

The header contains view tabs, project selection, and conversation or message search. The next toolbar contains controls for the active view:

| View        | Content toolbar                                                                                         |
| ----------- | ------------------------------------------------------------------------------------------------------- |
| Map         | Branch paths / Conversation relations, direction, display style, previous versions, and shared history  |
| List        | Previous versions and shared history settings                                                           |
| Growth tree | Conversation and branch selection, return to discussion, previous versions, recorded steps, and refresh |

Start new conversations from the host chat entry. Conversation Map provides actions for existing conversations and their branches.

## Three presentations

### Public group discussions

Opening Conversation Map in a group automatically shows public messages from every member, including non-primary Assistants. The scope stays within the current group; other groups in the same Project and private Assistant execution conversations are excluded.

- **Map** connects requests, replies and follow-ups; **List** uses public message order; **Growth tree** groups interleaved discussions under their actual parent messages.
- Filter by speaker, search messages and load earlier history. If a parent is outside the current page or filter, the view labels that relationship explicitly.
- Messages distinguish ordinary speech, requests, progress replies and final replies, with markers for resource cards and analysis results. Select a node and choose **Locate in group** to read its original text or card; **View related message** returns to the associated question.
- Group membership grants access to public discussion only. Private tool calls, prompts and execution details retain the separate authorization of the existing **Assistant processing records** entry. Group maps do not offer private-conversation branching or renaming.

The Project, branch and previous-version controls described below apply to individual Assistant conversations.

| View        | Best for                                                      | Presentation                                                                     |
| ----------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Map         | Discussion paths and conversation origins                     | Cards and connections, with Branch paths and Conversation relations perspectives |
| List        | Titles, recent questions, update times, and quick actions     | A directory with indentation, expansion arrows, and guide lines                  |
| Growth tree | Discussion forks and the Agents and activities behind a reply | Tapered branches, activity leaves, and a floating detail panel                   |

### The two Map perspectives

**Branch paths** follows actual message ancestry. It compresses shared prefixes into common segments and forks where paths separate. Use it to follow how a discussion developed in different directions.

**Conversation relations** shows conversation, branch, and question/reply nodes. It retains parent-branch relationships and uses dashed links for independent conversation origins. Use it to locate a conversation, branch, or exchange in relation to other records.

Both perspectives belong to the same Map tab. Switching to List or Growth tree and back retains the chosen perspective, including after a host reload. Existing `mode=tree` and `mode=graph` links open their corresponding perspectives.

Map supports vertical and horizontal orientation, zoom, fit view, and a minimap. The button at the center of each card's bottom border expands or collapses its children. Connections display existing relationships; dragging them does not change conversation relationships.

The **Display** menu offers Compact and Summary node styles. Compact emphasizes titles and short excerpts; Summary shows more question content and conversation context. Cards size themselves to their content, with full titles and timestamps available on hover.

### List and Growth tree

List rows show a type icon, title, update time, and quick actions on the first line, with a question or reply excerpt below. Expansion arrows and title selection operate independently. When a title has keyboard focus, use the left and right arrow keys to collapse or expand it.

Growth tree has **Discussion paths** and **Reply execution** layers. See the [Growth tree feature guide](/en/guides/conversation-trail) for their meaning and controls.

## Project and conversation selectors

Project selection and Growth tree conversation selection use searchable comboboxes. Search runs on the server within the authorized scope, including records not yet loaded into the dropdown.

- Scrolling near the bottom automatically appends the next page of 20 results.
- While the view remains open, loaded pages and scroll positions are cached by scope and search term. Reopening a popover or switching view tabs does not restart pagination.
- Clearing the search restores the cached unfiltered list. Refresh, data mutations, and host context changes invalidate the cache.
- Lists provide loading, no-match, retry, and keyboard selection states.
- Selecting another project clears the previous conversation, branch, and reply selection so that its execution tree does not remain active in the new project.

**The conversation selector searches titles. Header search searches conversation titles and user-visible message content.**

## Nodes and relationships

| Node         | Meaning                                          | Main information                                                                          |
| ------------ | ------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Project      | The project scope of the conversations           | Project name and update time                                                              |
| Conversation | An independent conversation                      | Title, latest user question on the current branch, and update time                        |
| Branch       | A discussion path within a conversation          | Name, owning conversation, latest question, update time, and current-branch indicator     |
| Exchange     | A user question and its subsequent visible reply | Question excerpt, owning conversation, and update time; select it to preview the exchange |

Branches can inherit messages along their ancestor paths. Inherited questions have an explanatory label. Enable **Show shared history** to see this content, or **Show previous versions** to include older discussion versions created by message edits.

An independent fork creates a new conversation. Its source connection records provenance without changing ownership. Branch paths connects a loaded independent copy to its exact accessible source segment; Conversation relations uses a dashed source link.

Conversations and branches can be renamed. Exchange titles use excerpts from user questions. Missing question text produces a placeholder, without calling a model to generate a title. Missing update times are not inferred.

## Search and message navigation

Header search covers accessible conversations in the selected project and the current Assistant's version family. It matches text fragments in titles, user questions, and visible replies. Results highlight matching text and show a location path through the project, conversation, branch, and message.

A message shared by several branches of one conversation appears once in search results. Choose which branch to open from that result. **Show previous versions** controls whether historical versions participate. Use **Search more conversations** to retrieve further results.

**Locate in chat** opens the corresponding conversation and exact branch, loads older history when needed, and scrolls to and highlights the target message. When the Workbench is maximized, the host first reveals the chat; on narrow screens it closes the Workbench panel covering the chat. Missing, inaccessible, or unreadable targets produce an explicit error.

## Conversation actions

| Action               | Available from                                  | Result                                                                                                                        |
| -------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Locate in chat       | Card or list quick actions, or exchange preview | Opens the conversation and branch; scrolls to and highlights a specified message                                              |
| Start side chat      | Branch quick actions or menu                    | Creates a branch in the same conversation from that branch's latest sealed reply                                              |
| Branch into new chat | Actions on a reply that supports branching      | Creates an independent conversation from saved reply state and copies history through that reply; project files remain shared |
| Rename               | Conversation or branch menu                     | Updates the conversation title or branch name                                                                                 |
| Copy link            | Action menu                                     | Copies the conversation, branch, and optional message location while preserving view and display parameters                   |

Side chats can start from running or paused branches; the source retains its execution state. A branch without a sealed reply returns an explanation. An independent fork requires a complete reply and available saved state. Unsupported state formats, missing state, or incomplete replies prevent the fork.

Pending requests block duplicate actions. Creation and branching retries reuse the original request identifier. Opening or locating a conversation preserves the Conversation Map tab, query, and layout. Browsing and navigation do not send messages or stop running branches.

## Permissions, state, and limits

- Projects, conversations, counts, search, and actions follow organization and resource authorization. Read, contribute, and manage operations use their respective permissions; renaming requires manage access. Sharing a link does not grant access.
- Message browsing includes user-visible content and excludes internal runtime inputs, private tool inputs, reasoning, and checkpoints. Public tool records available in Growth tree follow separate authorization and credential-redaction rules.
- The host saves project, search, and display preferences, together with Growth tree conversation, branch, and reply locations. Context changes refresh authorized data; stale responses cannot overwrite the new state.
- The interface follows the host's language, light or dark theme, and corner-radius settings. Tabs, menus, results, lists, and exchange previews support keyboard interaction. Narrow screens adapt secondary controls.
- Search scans visible history in pages; conversations with extensive history may take longer. Message navigation requires a host ChatKit version supporting that capability. Unsupported hosts display an explicit notice.

### Shared views for direct and group conversations

Both use the same map, list, growth canvas, search, and message details. Group conversations add a speaker filter and stay within the current group. Private branch editing, side chats, and Assistant execution inspection are not offered in this scope.

Authorized readers adapt their results into one map read model: `scope` identifies visibility, `nodes` represent conversations and messages, `edges` distinguish containment, branches, replies, and causation, `capabilities` describe available actions, and `pageInfo` carries pagination. All three views consume the same projection without changing access rights. Requests, progress replies, and final replies are message attributes; chronological order alone is not a reply or causal relationship.

Filtering or paging can leave a parent outside the loaded results. Its message remains visible and reconnects when the parent loads. Resource and result cards appear as public summaries and markers; use **Locate in chat** to view their full original content.

Single-chat execution details retain their dedicated trace model and authorization checks. The shared map projection does not convert tool calls or private runtime records into public group messages.
