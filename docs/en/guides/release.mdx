# Release Packages and Docker Images

## Docker image publishing

The repository publishes Docker images to:

- `ghcr.io/<owner>/xpert-api`
- `ghcr.io/<owner>/xpert-webapp`
- `ghcr.io/<owner>/xpert-nsjail-runner`

`<owner>` comes from `github.repository_owner`. For the upstream repository, that value is `xpert-ai`.

### Push `develop`

Pushes to `develop` build affected application images and run their health checks locally on the runner. Registry publication is limited to `main`.

### Push `main`

Every push to `main` publishes API, Web and NsJail production images after verification:

```bash
git checkout main
git push origin main
```

Published tags:

- `main`
- `latest`
- `sha-<full_commit_sha>`

### Numbered application images

Merging a Changesets versioning commit into `main` also publishes the matching
application version, such as `3.6.0`. Application image publishing runs on branch pushes.

### OLAP images

The dedicated `olap` workflow compares the current tag to the previous tag. It only publishes when OLAP files changed in that range, or when a commit in that range contains `[build olap]`.

### Pull from GHCR

Pull the image tag that matches the branch or release you want to deploy:

```bash
docker pull ghcr.io/xpert-ai/xpert-api:latest
docker pull ghcr.io/xpert-ai/xpert-webapp:main
docker pull ghcr.io/xpert-ai/xpert-webapp:latest
docker pull ghcr.io/xpert-ai/xpert-api:3.6.0
docker pull ghcr.io/xpert-ai/xpert-nsjail-runner:main
docker pull ghcr.io/xpert-ai/xpert-olap:develop-candidate
```

## Release npm Packages

This repository now uses Changesets for npm releases.

Current automation scope:

- CI publishes the managed public packages selected by Changesets
- stable releases use the `latest` dist-tag
- prerelease versions such as `3.9.0-beta.0` automatically use the prerelease identifier as the npm dist-tag, for example `beta`

## Create a changeset

```bash
pnpm changeset
```

Select only the public packages whose source or public API changed.

## Push the changeset to `main`

When a changeset reaches `main`, GitHub Actions opens or updates a release PR named `chore: version packages`.

## Merge the release PR

After the release PR is merged:

- `pnpm changeset:version` updates the package version and changelog
- the workflow builds each changed package into its configured publish directory
- npm publishing runs from the built output through trusted publishing

## Local verification commands

```bash
pnpm release:verify
pnpm changeset:version
pnpm release:publish
```
