Configuration validation, binding persistence, dispatch, business completion and delivery are separate outcomes. Saving does not start work; a visible catalog does not grant execution rights; model success does not prove business approval.

## Access and recovery

1. Resolve the authenticated user, tenant, organization and Project before reading catalogs, bindings or instances.
2. Validate template version, definition digest, adapter references and host features; save only form-allowlisted fields.
3. Before dispatch or decisions, recheck Project access, actual target, input versions, node and round state.
4. Queries and polling read facts. Provider refresh updates projections without business advancement.
5. Inspect an ambiguous original operation before creating replacement work. A cancellation request is distinct from confirmed cancellation.

Project read access does not grant access to every member's conversation or execution details. Portfolio reauthorizes each explicitly selected Project. Preferences and navigation are user- and Project-scoped; stale requests must not reopen old context after switching organization, account or Project.

## Diagnostics

| Symptom                                          | Check                                                                                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Tasks exist but a node has no dots               | Persisted node, round and Task Execution ownership; never infer from Task or Assistant                 |
| Execution succeeded but the node remains blocked | Execution outcome, business decision and historical snapshot separately                                |
| Empty catalog or unavailable binding             | Actual plugin loading, contribution source, host protocol, Project permission and role candidates      |
| Unavailable workbench entry                      | Provider presentation and authorization; historical nodes have no advancement entry                    |
| Long wait or unknown outcome                     | Durable intent, lease, original execution receipt and inspection; avoid blind redispatch               |
| Totals differ from instance sums                 | Deduplication, shared executions, current business scope and actual-start-time window                  |
| 403 or missing workspace                         | Correct organization context first, then actual access; never bypass authorization with database edits |

## Compatibility

Build and verify Contracts and SDK together. Use explicit host protocols and feature declarations, not version-number or name heuristics. A shared package release version does not establish interface compatibility.

`ProjectTaskExecutionTarget` is a union. Extend `ProjectTaskAssistantExecutionTarget` when an Assistant-specific target is required; narrow runtime variants with `kind`, not the presence of invocationId. External consumers must validate strict declarations and CJS, ESM and Bundler entry points.
