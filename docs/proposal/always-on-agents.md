## 下一来源的选择

普通“用户消息”分类留给有真实业务需求的来源。接入时先明确来源事实、稳定类型和版本、消费授权，以及它与现有聊天入口的归属关系，再验证三入口的分类和权限。后续来源继续按绑定选择接入；原 Trigger、会话消息、Invocation 回传、群聊投递、站内通知各自保留现有消费者。若需求只是跨系统排障，可以沿已有 delivery、operation 和 run 的引用追踪。
