# 租户集成的组织使用授权

租户是配置和治理边界，组织是业务使用边界。集成归属于租户，并不代表它自动向该租户的所有组织开放。组织使用租户集成，需要租户管理员同时授予使用范围和用途；原有的组织集成仍只属于其组织。

## 授权模型

租户管理员在系统集成详情的「组织使用授权」中选择：

- 不向组织开放：仅租户作用域可使用。
- 开放给本租户全部组织：包括后续创建的组织。
- 开放给指定组织：只允许所选的本租户活跃组织。

共享时至少选择一种用途：

| 用途            | 行为                                           | 典型场景                                  |
| --------------- | ---------------------------------------------- | ----------------------------------------- |
| `configuration` | 在服务端使用共享应用配置，作为用户账号授权入口 | Connector 的 OAuth App 配置、组织插件配置 |
| `invoke`        | 在业务运行时调用该集成                         | 通知工具、知识库检索、数据源与处理器      |
| `bind`          | 将消息入口绑定至 Assistant                     | 企业微信短连接、长连接触发器              |

共享授权不授予集成的编辑、删除、密钥查看权限，也不共享某个用户的 OAuth token。上游服务的账号授权、资源权限、接口范围和业务权限仍单独生效。这些用途是宿主的消费权限，并不新增上游服务原本不具备的功能。

## API 与运行时

- `GET /api/integration/available?usage=bind&provider=wecom` 校验用户当前组织访问资格后，返回本组织集成及明确授权的租户集成；没有组织的租户作用域请求只允许租户管理员。只返回选择所需的元数据和 `scopeLevel`，不返回 `options` 或密钥。额外的租户、组织查询参数会被拒绝。
- `PUT /api/integration/:id/sharing` 保存 `visibility / organizationIds / usages`。必须处于租户作用域，具有租户管理员角色和 `INTEGRATION_EDIT` 权限。服务端验证所选组织属于当前租户且处于活跃状态。
- 普通集成新增、更新不能修改共享策略或转移归属。管理列表和详情继续保持当前管理作用域。
- 旧的 `select-options` 也使用同一消费策略；`tenantOnly=true` 表示筛选获授 `configuration` 用途的租户配置，不绕过授权。
- 宿主 `readForUsage`、插件 `readConfiguration`、Connector 配置解析和知识库集成消费在服务端验证当前授权。选择器可见性不能代替执行时校验。
- 插件通过 `INTEGRATION_PERMISSION_SERVICE_TOKEN` 的 `readForUsage(id, usage, scope)` 使用集成。`scope` 必须来自宿主执行上下文或已持久化的绑定，不可来自模型工具参数、用户提交的租户 ID 或集成自身的归属。插件声明的 provider 与 integration ID 权限仍需满足。

旧的 `read()` 是内部兼容入口，供回调验签和传输层读取原始配置；它自身不代表组织消费授权。迁移其他插件时，必须在用户选择、调用、绑定和事件调度入口使用对应的授权 API，不能只替换下拉框。当前企业微信插件已接入这些入口；未迁移的第三方插件需要单独核查。

## 企业微信

触发器选择 `bind`，通知中间件选择 `invoke`。选项显示「本组织集成／租户授权集成」及绑定占用状态。一个企业微信集成只绑定一个 Assistant；其他组织看到同一个共享入口，并不意味着它可以同时绑定多个 Assistant。数据库唯一约束及条件更新避免并发发布覆盖已有绑定。

触发器发布使用宿主持久化 Assistant 的租户和组织作用域。收到企业微信消息后，执行作用域来自持久化绑定，不能因为集成归属于租户而将组织业务提升到租户作用域。发布、收到消息和延迟消息聚合实际调度时重新校验 `bind`；通知工具每次调用重新校验 `invoke`。

撤销授权后，新的选择、发布和受控运行时消费会被拒绝。已有集成、Assistant 配置和绑定记录保留，重新授权后可恢复使用。撤销不会回滚已经发出的消息，也不会自动取消已经进入执行阶段的任务或删除长连接配置。

## 升级和发布

1. 协同发布 contracts、plugin-sdk、宿主、Cloud 和企业微信插件。本次新增的 SDK 方法是可选方法，便于旧插件继续加载；新版企业微信消费入口在宿主缺少该方法时明确拒绝并要求升级，不降级为无授权读取。
2. `Integration.sharing` 是可空 JSONB 列，由现有 [schema-sync 部署步骤](development/database-migrations.md) 同步。先执行并验证结构升级，再启动新宿主。无需额外手工 SQL 迁移。
3. 历史记录的 `sharing = null` 表示尚未授权，对组织跨作用域消费默认拒绝。升级前盘点租户集成已有的组织使用与 Assistant 绑定，逐项授予所需组织和用途；不要批量默认开放全部组织。原有组织集成的同组织使用保持不变。
4. 在目标环境验证：指定组织可选择及执行、未授权组织拒绝、用途隔离、独占绑定冲突、撤销后拒绝以及重新授权恢复。短连接与长连接均需使用真实企业微信账号验收。

本实现没有新增配额分摊、计费、上游收件人/数据范围控制或历史授权审计页面。共享策略保存沿用实体更新信息；需要完整的授权变更历史时应接入专用审计能力。

## 配置界面验收

2026-10-31 在本地 Cloud、API 和已加载的企业微信插件上完成浏览器验收，使用占位短连接配置与未发布的 Assistant 草稿。

| 验收项                                             | 结果                                                   |
| -------------------------------------------------- | ------------------------------------------------------ |
| 短连接配置保存、刷新回显                           | 通过                                                   |
| 指定组织缺失、用途为空或无修改时禁用授权保存       | 通过；修复按钮的 `zDisabled` 绑定                      |
| 获授 `bind` 的组织选择企业微信触发器集成           | 通过，标明「租户授权集成」                             |
| 仅 `bind` 时通知选择器不可用，增加 `invoke` 后可用 | 通过                                                   |
| 排除当前组织、撤销授权                             | 通过；已有选择保留并显示「已选配置不可用」，失效项禁用 |
| 改为全部组织授权后恢复原有选择                     | 通过                                                   |
| 长连接租户手动配置、组织扫码／手动配置入口         | 通过，仅检查表单与入口                                 |
